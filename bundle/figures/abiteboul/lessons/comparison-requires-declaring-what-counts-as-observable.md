# Two systems become comparable only after you declare what counts as observable

**Lesson:** Arguments about whether two systems are equivalent, or whether one is more capable than the other, usually stall because the participants are comparing artifacts of different shapes and have never agreed on what the comparison is over. These works make the missing ingredient explicit and give it a name it already had: a view. A view is a mapping that says which parts of state and which occurrences are visible and what they look like when seen, and it can restructure as well as conceal, so it can carry two differently shaped systems into a common frame where a standard equivalence between behaviors finally has something to bite on. Comparison is thus a two-part act. Choose the observation interface, then compare through it. Skipping the first part is what makes the argument unresolvable.

What makes this more than tidiness is that the answer genuinely moves as the interface moves. Under an interface that exposes everything, so that two specifications must generate exactly the same behaviors step for step, the three process paradigms examined are mutually incomparable: none subsumes another. Under a more permissive interface that permits internal data and auxiliary actions to be hidden, the same comparison reverses so far that a bare core model with no explicit control mechanism at all can stand in for all three. Neither verdict is wrong. They are answers to different questions, and the interface is the question. The same machinery does the work in data integration, where every source is described as a view so that a request expressed against a single shared vocabulary can be rewritten into requests the individual sources understand, and it is the same mechanism the relational treatment introduces early as composition of queries.

Adopting this changes how you conduct technical comparisons and how you build compatibility layers. Before comparing two designs, write down the observation interface: which events are visible, which state is visible, what is deliberately invisible, and what internal activity is allowed to happen unobserved. Expect the ranking to change with the interface and say which interface you are using when you state a conclusion. When integrating systems you do not control, the durable move is to define each one as a view over shared terms rather than to negotiate a single common format, because a view is a thing one party can write about their own system without coordinating with anyone else. The unifying insight is that hiding is a legitimate and load-bearing part of a specification, since a claim of equivalence is only as meaningful as the list of things you have agreed not to look at.

The integration form appears in the data integration chapter of [Web Data Management](../works/web-data-management.md), where source-to-vocabulary relationships are stated as views and wrappers present every source through one abstract model; the underlying notion is introduced in the conjunctive query chapter of [Foundations of Databases](../works/foundations-of-databases.md).
