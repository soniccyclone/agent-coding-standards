# Translating a system into a general framework is a diagnostic instrument: the context you must thread names its irregularities, the freedom left over names its missing generalizations

**Lesson:** Landin's mapping of a real language into a small core is not only a semantics; it is a measuring device, and the measurements are the extra baggage the mapping is forced to carry. His translation threads two parameters through nearly every case. One sorts identifiers into several mutually exclusive kinds so that certain occurrences can be silently rewritten. The other carries what should happen after the construct currently being translated. Neither has anything to do with the core he is translating into. Both exist because the source language declines to say things out loud, and he says so directly: the classification would be unnecessary if calls to argument-less procedures were written with visible empty argument lists and if parameters passed unevaluated were written as the functions they are; part of it would be unnecessary if names declared with persistent storage were guaranteed distinct; the successor parameter and part of the label machinery would be unnecessary if a construct entered by a jump were guaranteed to be left by one. Each conditional-perfect sentence is a defect report.

The pattern generalizes past his subject because the mechanism is generic. Whenever a target formalism is regular and a source is not, the irregularity cannot vanish — it has to be carried somewhere, and where it goes is into ambient context that every case of the translation must accept, maintain and pass on. So the shape of a translator is a readout of its input language's honesty. The uglier the threading, the more the source relies on information the programmer had in mind and never wrote. Landin also points at a single specific wart — the handling of argument-less value-returning procedures appearing as arguments to other procedures — and identifies it as the reason one auxiliary definition needs an awkward extra case, which is the fine-grained version of the same measurement.

The instrument reads in the other direction too, and this is the part people miss. Landin's abstract program objects are deliberately more permissive than the source's grammar; he declines to filter out things the original would reject, notes that some of that license simply leads to undefined results, and notes that some of it is actually given a meaning by his translation. Constructs the source forbade turn out to be perfectly interpretable in the core, and he closes by saying the correspondence suggests new ways of classifying the language's features along with generalizations and alterations that language designers might want. A faithful model built on a more general foundation therefore tells you two different things at once: where the modelled system is arbitrary, and what it could have been had it not been.

The habit this produces is to treat every adapter, compiler, serializer and interop layer you write as a report on the thing being adapted. When a converter needs a mutable context object passed everywhere, ask what the source format leaves implicit that forces it — usually an ambiguity resolved by position, a default that depends on scope, or a name whose meaning depends on where it was declared. Those are the places to push for a change in the source rather than more cleverness in the converter. And when the target admits combinations the source refuses, do not automatically reject them as invalid input; check whether the refusal was ever principled, because an accidental restriction discovered this way is a free design lead.

**Source:** [A Correspondence Between ALGOL 60 and Church's Lambda-Notation: Part II](../works/correspondence-algol-60-church-lambda-notation-part-ii.md) — the discussion of the identifier-classification and successor parameters, each accompanied by an explicit statement of the source-language change that would render it unnecessary, the note attributing an awkward case to a specific irregularity in how argument-less value-returning procedures are passed, the deliberate decision to let the abstract program objects be more tolerant than the source grammar, and the concluding remark that the correspondence suggests reclassifications and generalizations for designers.
