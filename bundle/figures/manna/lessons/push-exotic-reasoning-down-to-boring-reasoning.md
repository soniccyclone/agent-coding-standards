# Layer a reasoning system so the exotic part is program-independent and the program-specific part is boring

**Lesson:** The architecture of Manna and Pnueli's proof system is more instructive than any individual rule in it. It splits into three strata: one that reasons about time and knows nothing about programs or data, one that reasons about the data domain and knows nothing about time, and one that knows about a specific program. Each stratum is closed under its own concerns. The temporal stratum is fixed once, proven complete once, and reused against every program forever; the data stratum is whatever theory of integers or strings or lists you happen to need; only the thin top stratum changes when the program changes. The dependency runs one way — the program-specific layer consumes the general machinery and never modifies it.

The payoff of that layering is where the real design idea lives: the program-level rules are built so that discharging them requires no temporal reasoning at all. Every premise of the safety rule, the response rules, the progress rules reduces to checking an ordinary implication between assertions about a state and its successor. The person applying a rule reasons about one transition at a time, in first-order logic, about primed and unprimed variables — no unbounded futures in their head. The unbounded reasoning was done once, inside the justification of the rule, and never resurfaces. Induction over positions in an execution is implicit in the invariance rule; well-founded induction is explicit but confined to a ranking function, one number per state. This is deliberate compression of what a human must hold in working memory, achieved by choosing where in the system the hard argument gets amortized.

The connection between strata is engineered to be loose in a specific way worth copying. The rule that lifts a state-level fact into the temporal system demands only that the state-level fact be *true*, not that it be *proven* by any particular prover. The temporal layer therefore does not depend on which decision procedure or SMT solver or hand argument establishes the data facts — you can swap the bottom out entirely. The authors are candid that this generality makes the whole system non-recursive unless you restrict what the assertions may say, which is the honest form of the trade: the abstraction boundary is worth the loss of mechanical checkability at the top level, and you buy the checkability back by constraining the layer below rather than by welding the layers together.

Someone who thinks this way, faced with any reasoning task that spans a hard global property and a mass of local detail, looks for the cut that puts all the hard global reasoning in a fixed, reusable, once-verified component whose interface to the per-instance work is a set of local, mechanically-checkable obligations. Verification conditions, type rules, refinement obligations, migration checks — the pattern is the same, and the quality of the design is measured by how dull the per-instance obligations are.

**Source:** [The Anchored Version of the Temporal Framework](../works/the-anchored-version-of-the-temporal-framework.md) — the introduction's decomposition of the proof system into general, domain, and program parts, and the program-part sections where the completeness claims are stated specifically as completeness relative to purely assertional reasoning. [Completing the Temporal Picture](../works/completing-the-temporal-picture.md) sharpens the same argument in its introduction, where the older system's residual obligations in temporal rather than state-level reasoning are named as the reason practitioners abandoned it for other formalisms — the stated purpose of the new rule set being to leave nothing behind but assertional obligations.
