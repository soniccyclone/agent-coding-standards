# Make self-simulation safe by reserving the budget first and giving surrender a definite answer

**Lesson:** A construction that runs arbitrary other constructions — an interpreter, a sandbox, a supervisor, anything that takes a description of a process and executes it — cannot be shown to terminate by inspecting what it runs, because what it runs is arbitrary. Termination has to come from the frame instead, and the frame is built in a fixed shape. First reserve the resource: mark the boundary of what this run is allowed to touch, and let every later phase be physically confined inside those marks. Then decode the description into that reserved space, and if the description will not fit, stop right there. Then run the simulation inside the space, with a separate meter that counts the simulated steps and is itself stored inside the reservation, so that exhausting the meter is detectable rather than merely eventual. Reserve, then decode, then run — each step guarded by the previous step's boundary.

The load-bearing part is that every way of running out gets a definite answer rather than an error. The description doesn't fit: definite answer. The simulation wants more room: definite answer. The step meter overflows: definite answer. This is what makes the whole thing total, and it is the reason such a construction can be a member of the very class it reasons about: it never fails to decide, so it is a legitimate inhabitant of the bounded world, which is exactly the property the argument needs. Treating exhaustion as an exceptional condition instead of a defined outcome would break that, because a construction that sometimes has no answer cannot be compared against the constructions it simulates. The step meter deserves particular note — bounding a run by counting its steps in storage that provably fits under the ceiling is what converts "this might loop forever" into "this halts, possibly with a surrender verdict," and the surrender verdict costs you nothing as long as you arranged for it to fall on inputs you do not care about.

Two further disciplines come with the pattern. The counting is done in whatever representation makes the meter demonstrably fit, so the encoding choice is part of the correctness argument rather than an implementation detail. And the technique is not the phenomenon: when the same self-simulation cannot be built at all — because the machinery being studied is too weak to interpret descriptions of itself — the conclusion is not that the question is closed but that a different route is needed, typically an argument that the restricted machinery must eventually fall into repeating behaviour and therefore cannot distinguish inputs that differ only inside the repetition. Keep the goal and change the method, and be explicit that the two results now rest on different foundations, because they will have different strengths.

**Source:** [Hierarchies of Memory Limited Computations](../works/hierarchies-of-memory-limited-computations.md) — the three-phase diagonalisation constructions in the proofs of the two hierarchy theorems, where the bound is marked off first, the decoded description and the simulation are both confined between the markers, the simulated steps are counted in a fitted representation, each of the three exhaustion cases is given a definite verdict with the remark that this is what guarantees halting; together with the later passage conceding that no such construction is available for the restricted-storage model and substituting a periodicity argument instead.
