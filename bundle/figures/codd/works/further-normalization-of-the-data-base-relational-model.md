description: Introduces second and third normal form, giving database designers a stepwise procedure for splitting relations so that each fact about an entity is stored in exactly one place. The motivation is practical rather than purely mathematical: redundant or awkwardly-structured relations make update anomalies and inconsistency more likely, and normalization is offered as a discipline for avoiding that. This became the backbone of standard relational database design practice for decades.
