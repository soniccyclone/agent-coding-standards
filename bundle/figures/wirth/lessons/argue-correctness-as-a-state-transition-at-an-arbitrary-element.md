# Argue correctness as a state-to-state transition at an arbitrary element

**Lesson:** An algorithm that temporarily destroys the structure it is working on cannot be checked by reading it and forming an impression, because at no intermediate moment does the data look like anything you recognize. Tracing an example is not much better: it convinces you about one shape and tells you nothing about the shapes you did not draw. The technique that scales is to stop reasoning about the whole run and instead fix an arbitrary element of the structure, describe exactly the state of the world when the algorithm arrives at it, describe exactly the state when it leaves, and take the claim that the algorithm converts the first into the second as a hypothesis. Then trace the algorithm's steps at that one element, permitting yourself to *assume* the same hypothesis for the sub-elements it descends into. If the assumed transitions for the parts compose into the claimed transition for the whole, you are done — the argument applies at every element including the outermost.

Two aspects of this are the working part rather than the ceremony. First, the states must be written down as concrete configurations — which fields point where, what the auxiliary variables hold — not as informal summaries like "the subtree has been processed", because the whole difficulty of the algorithm is that its intermediate configurations are strange, and a summary hides exactly what is strange. Once written out, the sequence of configurations between arrival and departure is the proof, and it also reveals things you would otherwise not know, such as how many times the algorithm passes through a given element, which in turn tells you how much per-element state the algorithm must be keeping.

Second, the composition step above is valid only where the sub-elements actually exist, so the argument is incomplete until the degenerate cases are checked separately, one at a time and explicitly: no first sub-element, no second, none at all. These are exactly the cases where some of the intermediate configurations are skipped, and enumerating which transitions are bypassed in each case is what closes the argument. It is also where such algorithms actually break, so the part of the reasoning that feels like a formality is the part that finds the bug. The habit worth extracting: any procedure that leaves its data invalid partway through owes this kind of argument, and the effort of producing it is bounded by the number of distinct configurations at one element rather than by the size of any input.

**Source:** [Project Oberon](../works/project-oberon.md) — section 8.3's justification of the pointer-inverting traversal, which poses the question of how the claims about the algorithm are convincingly supported and answers that the best way is to analyse the algorithm at an arbitrary node; the hypothesis that from an initial state the algorithm reaches a final state differing from it by the node and its two subtrees having been marked and by the exchange of the two working pointers; the walk through six successive configurations at that node, in which three transitions follow directly from the algorithm's pointer rotation and two follow from applying the hypothesis to the subtrees, with the observation in passing that the node is visited three times and that progress is recorded by the mark value advancing from zero to three; the conclusion that the hypothesis holding for the subtree steps makes it hold for the whole step and therefore for the root; and the closing check that the argument relies on the algorithm behaving correctly when the first subtree is empty, in which case one configuration is skipped, and when the second is empty as well, in which case another is.
