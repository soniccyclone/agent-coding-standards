# Define each addition by translation, and give the top level no privileges

**Lesson:** There is a cheap way to add notation without adding meaning, and it should be the default: for each new construct, give a rewriting into constructs that already exist, and let that rewriting be the definition rather than a commentary on it. A conditional-controlled repetition can be defined as a conditional whose branch is the body followed by the same repetition again; a counted repetition can be defined the same way with the counter's successor. The self-reference is not a trick, it is what lets one line define an unbounded behavior in terms of machinery already present. Two things follow that are worth the effort of arranging. The semantics of the addition is settled by construction and cannot drift from what the core means, since there is nothing else for it to mean. And the count of genuine primitives stays auditable, because anything defined by translation is not one — a design with many constructs and few irreducible ones is a different object from a design with many of both, and the distinction is invisible unless the translations are written down.

The companion discipline is refusing to let the outermost level of a system be a special case. If a complete program is defined as an ordinary named unit with its heading removed, then everything already established about such units — scoping, nesting, what may be declared inside — applies to programs with nothing further to say. If the standard input and output are the program's formal parameters, then supplying them is parameter passing rather than a separate concept about how programs communicate with the outside. Whole categories of rules do not need to be written, and every rule not written is one that cannot conflict with another.

The same instinct handles the awkward corners that usually attract new mechanisms. Names supplied with the system are best treated as declared in a scope enclosing the user's text, and then the question of what happens when someone redefines one has already been answered by the ordinary scope rules — no privileged namespace, no conflict, no special dispensation, and an implementation is free to supply extra ones without changing the language. When a convenient abbreviation for repeatedly naming parts of the same aggregate is wanted, define it as opening a scope in which those part-names are visible, reusing scope again instead of inventing an abbreviation mechanism with rules of its own. The general test to apply to any proposed addition: name the existing concept it can be expressed as an instance of. If there is one, the addition costs notation only. If there is not, you are adding to the semantic core and the price is much higher than it looks, because it will interact with everything already there.

**Source:** [The Programming Language Pascal](../works/the-programming-language-pascal.md) — the definitions of the while, repeat and for statements by stated equivalences that rewrite each into an if statement containing the body and the same construct again; section 12 defining a program as a procedure declaration without a heading, together with section 7's treatment of the standard input and output files as the program's formal parameters; section 10.1's statement that standard procedures are assumed declared in a scope surrounding the program so that a redefinition raises no conflict and implementations may add their own; and section 9.2.4 defining the with statement as effectively opening the scope containing the record's field identifiers.
