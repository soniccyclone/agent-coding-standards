# Route a request through its context and the context arrives already computed

**Lesson:** Forwarding a request down a containment hierarchy instead of delivering it straight to its target looks like pure overhead — the same request, retransmitted at every level, arriving eventually at the place you could have addressed directly. The overhead is real and the usual defences for it are about coupling: the sender need not hold a reference to the target, levels can be inserted and removed. But there is a second payoff that is easy to miss and often larger, and it is worth designing for deliberately. A request that walks the containment path has, by the time it arrives, been touched by every enclosing level in order. If each level adds its own contribution to the request as it passes, the target receives a fully accumulated description of its situation without asking anyone for it.

That is a structural inversion worth naming. Position, visibility, permission, resource limits, clipping region, effective configuration — these are all facts that no single level owns, because each is composed from a chain of contributions running from the outermost container down to the thing itself. If requests are delivered directly, the recipient has to reconstruct that chain by walking upward, which means it must hold a parent reference, know the composition rule for every attribute, and repeat the walk on every request. If requests descend, the chain is walked once, forward, as a side effect of delivery, and each level applies only the composition step it is competent to apply. The recipient ends up needing no upward reference at all. What was a query becomes an accumulation.

The same passage through the context buys a second thing: a level can behave differently according to where it sits, because a level sees requests destined for everything beneath it and may alter them, wrap them, or handle them itself. That is what lets one subtree operate under a different regime from its sibling without either the sender or the leaves knowing — the difference is installed at the level that governs the subtree, and it applies to everything routed through. Direct delivery has no place to install such a thing except in the leaves themselves, which multiplies it by the number of leaves.

The cost side should be stated with equal precision. Every level on the path is now a mandatory participant, so a level that mishandles forwarding breaks everything below it, and the accumulation only works if every level agrees on what is being accumulated and in what order. That agreement is a contract as binding as any interface, and it should be written down as one. The rule for when the trade is worth taking: route through the context when the request's meaning depends on facts composed along the path, and deliver directly when it does not — a request whose interpretation is context-free gains nothing from the trip and pays for it anyway.

**Source:** [Project Oberon](../works/project-oberon.md) — appendix A.2's argument that because every visual object is a possibly indirect component of the display space, a message directed at any of them can be sent to the global display space with an implicit forwarding obligation, and that by the moment of its arrival the message has passed the entire context step by step; together with the two benefits drawn from that fact — that context-oriented processing can be done incrementally, instanced by accumulation of relative coordinates and computation of overlapping masks, and that context-dependent message handling becomes possible, instanced by a visual object behaving differently in a developer context and a user context — and the accompanying handler sketch in which each frame updates the context pointer and accumulates coordinates in the message before passing it to its descendants.
