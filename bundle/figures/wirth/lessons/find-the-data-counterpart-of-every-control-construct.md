# Find the data counterpart of every control construct, then carry the discipline across with it

**Lesson:** The ways of composing behaviour and the ways of composing data are the same small set of operations wearing different clothes. Naming one component is assignment on one side and a scalar on the other. Listing a fixed set of differing parts is a compound statement and a record. Replicating a known number of identical parts is a counted loop and an array. Choosing between alternatives is a conditional and a discriminated variant. Repeating an unknown number of times is a while loop and a sequence. Once you see the correspondence as a table rather than as a set of coincidences, it becomes a generator: for any construct on one side that has no partner on the other, ask what the partner would have to be. Doing this with the procedure — whose distinguishing property is that it can invoke itself — is what produces the recursive data type, a type one of whose components is of the type being defined. That is a discovery method, not a mnemonic, and it is worth running deliberately whenever a language or a design feels lopsided.

The correspondence also transfers obligations, which is where most of its value is. A recursive procedure that never tests anything never terminates, so a conditional is not a stylistic feature of recursive code but a structural necessity. Read across the table and the same necessity lands on the data side: a recursive type with no alternative branch has only infinite values, so the discriminating case is the only thing that can bound it, and it is an inevitable companion of every recursive definition rather than an optional refinement. The reasoning that establishes one fact establishes the other, because they are the same fact stated about two projections of one structuring vocabulary. When you find yourself proving something about control flow, check what it says about data, and vice versa; half the time you get the second result for nothing.

The last row of the table is the one that costs something to accept. Beneath the disciplined constructs sits the unrestricted jump, which can produce any control pattern at all, including ones no combination of the disciplined constructs can express, and which is therefore powerful in exactly the way that makes reasoning about a program hard. The data-side partner of the unrestricted jump is the explicit reference, which likewise produces any linkage at all, including cyclic ones that no purely recursive definition can describe. If you accept that unstructured jumps buy their power at a cost in comprehensibility and should therefore be confined and justified, consistency requires the same posture toward unrestricted references — and the practical consequence is the same, that a traversal over a structure you allowed to become cyclic can fail to terminate for precisely the reason an unconstrained jump graph can. The general habit: when a mechanism's power comes from removing a restriction rather than from adding a construct, look for its counterpart in the other half of the language, and expect it to have imported the same hazard under a different name.

**Source:** [Algorithms and Data Structures](../works/algorithms-and-data-structures.md) — section 4.1's stated analogy between methods for structuring algorithms and for structuring data, its question of what data structure corresponds to the procedure statement and the derivation of the recursive data type from that question, the argument that the variant facility is the only means by which a recursive data structure can be bounded and is therefore an inevitable companion of every recursive definition, paralleled with the necessity of a selective statement in every recursive procedure; and section 4.2's table of correspondences, which places the general graph linked by pointers opposite the GOTO statement, together with the surrounding remark that pointers permit any data structure including rings as GOTO permits any program pattern including loops, and the note that manipulation of cyclic structures can lead to nonterminating processes.
