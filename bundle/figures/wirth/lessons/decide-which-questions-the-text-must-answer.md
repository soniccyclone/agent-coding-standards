# Decide which questions the text alone must answer, then shape every construct to preserve that

**Lesson:** Before designing constructs, decide which questions about an artifact must be answerable by reading it rather than by running it. That list is the real specification, because every construct then has to be shaped so as not to destroy any entry on it, and a great many otherwise arbitrary-looking design choices become forced. The clearest case is component selection. When parts of an aggregate are chosen by a computed value, their type must be uniform, since nothing in the text says which part you will get. When you want parts of differing types, the selection has to be by a fixed name written in the program — not because names are friendlier, but because a computed selector would make the type of the result undecidable from the text. The shape of the selector follows from the property you refused to give up. Run the same reasoning over the whole design and the family of structuring methods falls out of a single question: what is the selection mechanism, and what does it let a reader know? Selection by computed index, selection by written name, no individual selection at all with only a membership test, one component reachable at a time through a moving position, components existing only from the moment they are created and reached through references bound to where they came from — five different answers to one question, each with different static knowledge attached.

The discipline shows up again as a set of restrictions that look unrelated until you see what they have in common. Assignment demands identical types with a short, explicitly enumerated list of exceptions, so no conversion happens that a reader has not been told about. A function may not assign to anything non-local, which turns "does calling this change something else" from an investigation into a fact about the language. A label's scope stops at the enclosing procedure, so entering a procedure other than by calling it is not merely bad practice but unwritable. A reference is bound to the specific collection it can point into, so what it may denote is known without tracing execution. The body of a counted repetition may not modify the control variable or the bound, so the announced number of iterations is trustworthy. None of these makes the language more powerful, and every one of them converts a question that would need analysis into a question with a textual answer.

The general method is worth extracting from the particulars. Take any property you want cheaply available — the type of a value, the set of things a piece of code can affect, the number of times something runs, the set of objects a reference can denote — and ask what a construct would have to permit in order to make that property undecidable by reading. Then decline to permit it. This is a stronger design principle than after-the-fact analysis, because it puts the guarantee in the definition rather than in the cleverness of a tool, and it means the property is available to a human reader and not only to a program. And it is worth noticing what it costs: each such restriction rules out some usage that would have been convenient somewhere. That is the trade being made deliberately, and the reason to make it is that a question answerable from the text is answered once, whereas a question requiring analysis is answered again by every reader who wonders.

**Source:** [The Programming Language Pascal](../works/the-programming-language-pascal.md) — the summary section's statement that structuring methods differ in their selection mechanism, with the explicit reason that a record selector contains no computable value so that the type of a selected component is evident from the program text without executing the program, and the five structuring methods characterized by their selection and accessibility properties; plus the assignment rule requiring identical types with two enumerated exceptions, the prohibition on functions assigning to non-local variables, the restriction of a label's scope to its enclosing procedure making it impossible to jump into a procedure, the binding of each pointer type to a specific class variable, and the rule that a for statement's body must alter neither the control variable nor the final value.
