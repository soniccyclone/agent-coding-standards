# A hint is a cache that owes nothing to coherence

**Lesson:** Keeping a derived value to avoid recomputing it normally drags in an invalidation protocol: everything that could falsify the value must know the value exists and must go and correct it, which couples components that had no other reason to know about each other and produces the class of bug where one path forgot. There is a way to keep the saving and refuse the protocol entirely, and it is a decision about status rather than about mechanism. Declare the stored value non-authoritative — a guess, believed by nobody, correct most of the time — and require every use of it to establish its validity before relying on it. Nothing then needs to invalidate it, because nothing was ever entitled to trust it. The obligation moves from many writers to one reader, and one reader is a place you can actually be sure about.

The design becomes a question of arranging for the check to be trivial and the miss to be ordinary. The check has to be a direct comparison against the authoritative state, cheap enough that paying it on every use is still far below recomputing — and, importantly, the authoritative state must be something you were going to have in hand anyway, or the check reintroduces the cost it was meant to avoid. The miss path must be the plain, always-correct procedure, taken without ceremony: search for the right thing, and if it is not there, obtain it. A guess whose failure requires special handling is not a guess, it is a cache with the invalidation bugs still present and the honesty removed. And because a guess is only worth its check when it is usually right, its value comes from a claim about behaviour — that use is overwhelmingly local and sequential — which should be stated so it can be re-examined when the workload changes.

There is a second, weaker grade worth distinguishing, because it is cheaper still. Some derived values are consulted not to obtain a fact but to choose among equally correct courses of action — where to allocate next, which candidate to try first, what order to search in. These need no validity check at all, because there is no wrong answer, only a worse one; a stale value costs some performance and cannot cost correctness. Recognizing which grade you are in is the whole of the work: if being wrong changes the *result*, you owe a check at every use; if being wrong changes only the *cost*, you owe nothing, and should resist the instinct to maintain it carefully. Deciding this explicitly is what keeps a system's performance machinery from silently becoming part of its correctness argument.
