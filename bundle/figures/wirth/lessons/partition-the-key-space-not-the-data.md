# Partition the key space, not the data, and the structure stops depending on its history

**Lesson:** There are two ways to decide where a structure divides. You can let the dividing point be a value taken from the data — the element sitting at that branch decides which side everything else falls on — or you can fix the dividing points in advance by repeatedly halving the range the keys are drawn from, independent of any element. The first is the familiar choice and it is what makes a structure's shape depend on the order in which items arrived. The second changes the character of the structure entirely, and the changes are worth enumerating because they are the reason to consider it.

Depth stops being a function of how many elements you have and becomes a function of how wide the key range is: each level halves the remaining interval, so the number of levels is bounded by the logarithm of the range, which for machine integers is a small constant fixed by the word size no matter how many elements are stored. Maintenance stops rippling: because the dividing points never move, inserting an element cannot invalidate any other element's placement, so the work of an insertion is confined to the single path from the root to where it lands rather than propagating sideways or upward. And the structure becomes canonical with respect to its contents, which removes an entire category of reasoning about pathological insertion orders — there is no bad order, because order does not affect the result.

Two further points come with the technique. The interval belonging to a position is determined entirely by the route taken to reach it, so it need not be stored at all: carry it down as arguments, halving as you descend. Any quantity that is a function of the path is available for free during a traversal, and storing it in the elements is redundancy you will then have to maintain. The cost side is that the approach requires the key range to be known and bounded in advance, and it distributes elements by where they sit in the key space rather than by how many of them there are, so a heavily clustered population produces long thin regions of structure. Both of those are real restrictions, and the pattern to notice is that accepting a restriction on the problem — a bounded range here, an anchored side of a query region there — is what buys the simple structure with clean bounds, where the unrestricted version demanded an intricate mechanism that saw little practical use.

**Source:** [Algorithms and Data Structures](../works/algorithms-and-data-structures.md) — section 4.8's radix priority search tree: the observation that the dividing line need not be the node's own coordinate, the association of an interval with each node whose descendants must lie in its halves so that the dividing value is the interval's midpoint, the resulting bound on tree height by the logarithm of the coordinate range and its identification with the machine word length for integer coordinates, the stated decisive advantage that maintenance operations are confined to a single spine because the dividing lines have fixed values irrespective of the inserted nodes' coordinates, and the note that the interval bounds are not recorded in the nodes but computed during each search and passed as additional parameters of the recursive procedure; together with the same section's preceding decision to delimit the data space by a bounded rectangle and to anchor one side of the enumeration region, in place of the unbounded general problem whose balancing scheme was very intricate and hardly used.
