# Types and program assertions are one continuum, divided by a decidability frontier you get to choose

**Lesson:** Static type systems and program logics developed as separate trades with separate literatures, and the separation is an accident. Both attach claims to program points; both are about which states a program may be in; and once type systems began describing states rather than values — recording what a command does to the shape of storage, so that executing a command changes a state's type — the notational gap closed enough to be embarrassing. The unifying observation is semantic: a specification's invariant induces an equivalence on states, treating two as interchangeable when both satisfy it and agree on what is being computed, and that is the same construction used to give meaning to types. The productive question is therefore not which discipline to use but whether the dividing line can be erased, and short of erasing it, where to draw it deliberately.

Where it lands is a decidability question with sharp, measurable edges, and this is the practical content of the continuum. In the assertion language surveyed here, admitting quantification while omitting the resource-separating operators leaves validity not merely undecidable but not even recursively enumerable — no axiomatization is possible. Admitting the separating operators while forbidding quantifiers gives an algorithmically decidable language, whose model-checking and validity problems sit at identifiable complexity classes that shift as each operator is added. That is the design dial. A checkable fragment is not something you hope emerges from your specification language; it is a sublanguage you carve out on purpose, knowing what each construct costs, so that routine claims get discharged mechanically and only the claims that genuinely need human argument are left to one.

The continuum also settles what to do about information that exists solely for the argument. Proofs of low-level code want to record things the machine does not need — which addresses are live, which begin a record, which are of a given kind — and the temptation is either to store them at runtime or to switch to a higher-level language that tracks them for you. The better framing is that this is exactly what types are: facts checked before execution and then discarded. So introduce such facts as annotations required by construction to be incapable of influencing any computed value or any branch, which makes their erasure sound rather than hopeful. The reward is not only cleanliness: because a verified program cannot fault, the runtime apparatus that would have detected faults becomes provably unnecessary and can be removed. Proof is not merely a source of confidence about a system; done properly it deletes machinery from it.
