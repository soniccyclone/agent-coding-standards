# Push the type discipline into the grammar, and the safety of inlining becomes a theorem about which production could have produced each hole

**Lesson:** "Expanding a call in place produces something still well formed" is the kind of claim that gets asserted and never proved, because with a plain grammar there is nothing to prove it from — the grammar knows about statements and expressions, while the property depends on types and binding, which live somewhere else entirely. Fix that by moving the type discipline into the description of well-formedness itself: let the classes of phrase be indexed by type, so that for each type there is a class of things that establish it, a class of occurrences bound by those, and a class of phrases that can supply it. The metavariables ranging over types get their own grammar, one level up. Now a claim about substitution is a claim about derivations, and derivations are things you can do induction over.

The proof then takes a shape worth learning independently of grammars. For each kind of hole, ask which productions could possibly have described an occurrence of that kind. Because the classes are indexed finely enough, the answer is normally a single production, and that production names exactly the class of phrase that may be dropped in — so substitution is safe by construction, with no case analysis over what the substituted phrase happens to look like. Where more than one production applies, the extra cases tell you the fix rather than defeating you: an occurrence admitted only in a tight position needs the replacement wrapped in brackets, an occurrence admitted only as an indivisible statement needs it wrapped in a compound. The wrapper is not a defensive habit picked up from experience with macro expansion; it is computed from the gap between the class of the hole and the class of the filler, and where the classes coincide, no wrapper is needed.

The same move settles the corresponding question about the calling convention. Once the parameter list's types determine the callee's type, and the callee's type determines what an argument list must supply, the substitution the expansion performs is type-correct because the derivation of the call already said so — you do not check it, you read it off. That is the payoff of building the invariant into the notation rather than checking it afterwards: the property stops being something to verify per instance and becomes something no instance can violate.

**Source:** [The Craft of Programming](../works/the-craft-of-programming.md) — Appendix B.3, which introduces a two-level grammar in the style of van Wijngaarden's Algol 68 definition, with production schemas whose metavariables range over phrase types that are themselves described by productions, giving for each phrase type a binder class, an identifier class and a phrase class; B.3.5 then proves that type-correct substitution preserves syntactic correctness by observing that for each phrase type only one production can describe a non-binding identifier occurrence, and reading off from those productions that the replacement must be parenthesized when the type is an expression, enclosed in a compound when it is a statement, and left alone otherwise — with the chain from formal parameter list to procedure type to actual parameter list establishing that the copy rule's substitution is type-correct.
