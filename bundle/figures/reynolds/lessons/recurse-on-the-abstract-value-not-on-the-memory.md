# Say what the program is about before you say how it is stored, and define the link by recursion on the abstract value

**Lesson:** Describing the shape of a program's data — which cells point where, what does not overlap what — is never enough to say what the program does. That requires a second, separate layer: the mathematical objects the program is computing with, defined on their own terms without reference to storage, plus a predicate connecting each such object to the arrangements of memory that represent it. Keeping the two layers apart is a discipline about vocabulary as much as structure, and it pays immediately in that a single word stops doing two jobs. The abstract objects get one set of names, the faithful representations get another, the representations that admit sharing get a third, and a claim like "this routine turns a shared arrangement into an unshared one representing the same object" becomes sayable instead of confusing.

The technique for defining the connecting predicate is where the leverage is: recurse on the structure of the abstract value, not on the shape of the memory. The base case says which arrangement represents the trivial value; the step says an arrangement represents a composite value when it splits into a piece for the head and a separate piece representing the rest. Two things follow that would be painful otherwise. Composition laws — an arrangement represents a concatenation exactly when it splits into arrangements for the parts — are provable once by induction on the value and then reused everywhere, so proofs about programs become algebra over these laws rather than fresh reasoning about cells. And genuinely different memory layouts for the same abstract values, forward-linked, doubly linked, or with the two links compressed into one by an invertible combination, come out as variations on the same recursive scheme, so the differences stay confined to one clause instead of propagating through every proof.

The choice of abstract value is a design decision with consequences, not a formality. The same memory arrangement can be taken to denote the sequence of data it holds, or the sequence of *locations* those data occupy, and the second choice makes properties statable that the first cannot express — an invariant that the locations are unchanged says the algorithm rearranged links without moving contents, which is a considerably stronger claim than the data-level version and captures what "in place" was supposed to mean. So when a property you care about resists statement, do not immediately elaborate the representation predicate; check first whether you have chosen the wrong abstract objects. A well-chosen abstract layer also tends to be more local than expected, describing only the cells that carry the structure and leaving the payload cells to a separate description that can be composed in when needed.
