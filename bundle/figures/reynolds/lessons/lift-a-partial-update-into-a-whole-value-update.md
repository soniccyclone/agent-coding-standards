# When a rule breaks on updating part of a thing, lift the update to the whole value instead of patching the rule

**Lesson:** A clean rule for updating a named thing — to know what must hold before, take what must hold after and substitute — collapses the moment the target is a *component* selected by a computed index. There is nothing to substitute for, because the thing being changed has no name; it has a name plus a subscript, and whether some other name-plus-subscript refers to the same location depends on values not known until run time. Patching the rule means enumerating cases: same index, different index, and the enumeration multiplies as soon as two structures might be the same structure. The way out is not a bigger rule. It is to stop modelling the operation as a partial change and model it as a total one: assigning to a component is assigning to the whole container the value that agrees with the old value everywhere except at that one position. Now the target has a name again, the original rule applies with no modification, and the aliasing case analysis falls out of the definition of the modified value rather than being written into the rule.

The move is worth recognizing as a general technique, because the pattern recurs far outside array assignment. Whenever reasoning about a change to a piece of something gets tangled, ask what the change would look like as the production of a new whole value, described in terms of the old one. A record with one field replaced, a map with one binding overridden, a document with one node substituted, a configuration with one key overridden — each admits a compact description as a function of the previous whole, and each becomes reasonable-about at a stroke, since the operations on whole values obey algebraic laws that operations on locations do not. Those laws are the second dividend: overriding the same position twice keeps only the later value, overrides at distinct positions commute, overriding a position with the value it already has changes nothing, and an exchange of two positions leaves the set of contained values untouched. Facts like these are what let an argument skip steps.

Two cautions keep the technique honest. First, adopting the whole-value description for *reasoning* does not oblige you to adopt it for *execution*: the operation still compiles to a single store, and the total-value picture is a device for thinking, deliberately kept out of the executable language so that nobody accidentally writes a program that copies an entire structure to change one slot. Second, the lifted rule says nothing about whether the position exists. That obligation does not disappear, it just stops being the rule's business, and you have to discharge it separately — which is the honest arrangement, since existence of the target and correctness of the value are genuinely two different questions.

**Source:** [The Craft of Programming](../works/the-craft-of-programming.md) — Section 2.3.2, which shows the simple assignment rule failing on assignment to an array element because the required precedent depends on whether two subscripts are equal, then recovers it by treating an element assignment as assignment of a modified function to the entire array, gives the laws governing single-argument variation including idempotence, commutation at distinct arguments and preservation of the image under exchange, and closes by explaining why whole-array assignment is nonetheless kept out of the programming language.
