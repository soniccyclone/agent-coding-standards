# When a precise definition answers questions your description never asked, believe the definition

**Lesson:** Prose descriptions of a feature cover the cases the designer had in mind. A precise definition covers all of them, including the ones nobody considered, and it settles those cases whether or not anybody notices. The example here is an early-exit construct described informally as: bind a name to an escape operation, evaluate a body, and if the operation is ever invoked, abandon the body and take its argument as the result. That description is silent on what happens if the body, rather than invoking the operation, *returns* it — or returns something else able to invoke it later. The interpreter that defines the construct is not silent: it specifies the behaviour exactly. And the specified behaviour is not a bug to be legislated away; invoking an escape after its expression has finished is what makes coroutines and search with backtracking expressible. So a definition outrunning the intention that motivated it should be read as a source of new capability, not as an error to be patched back to the prose.

The reason a definition can do this is that it commits on things prose leaves as scenery. Here the commitment is the reification of the pending remainder of the computation, and that same commitment explains a hard limit discovered along the way: the construct cannot be defined at all in the recursive formulations of the interpreter, only in the ones where what-happens-next is an explicit value. In those, the information required to abandon a computation exists but is diffused through the call structure and cannot be manipulated. That is a general diagnostic worth keeping: when a feature seems impossible to add without cheating — importing the very feature into the substrate you were defining it in — the obstruction is usually that some state you need is implicit in your control flow rather than absent, and reifying it makes the feature fall out almost trivially. With the remainder available as a value, abandoning a computation is nothing more than declining to use the remainder you were handed and using an older one instead.

The same trust is warranted in the other direction, when a definition asserts something you cannot yet justify. The recursive binding construct here is characterized by a property that refers to the very thing it is defining, which is not a definition at all in the ordinary sense — one is owed a proof that anything satisfies it and an account of whether the solution is unique, and the machinery for that is deferred. Rather than weakening the construct to something immediately respectable, the honest move is to state the circular property, flag the debt, and continue — and to note that a later, more explicit formulation of the same construct will discharge it. Circularity you have named and bounded is workable; the mistake is either pretending it is not there or refusing to proceed until it is gone.
