# A guard that skips already-finished work makes the contract relative, so invent the relativized concept before attempting the proof

**Lesson:** The obvious recursive definition of a closure — this thing, plus everything reachable from its immediate neighbours — turns into a non-terminating procedure the moment the structure has a cycle. The standard repair is a guard: keep a record of what has been visited and return immediately on anything already in it. The repair is correct, it is two lines, and it quietly destroys your ability to state what the procedure does. The unguarded version computes a function of its argument alone. The guarded version computes something that depends on the accumulated record as well, and no wording in terms of the original concept will describe it, because the original concept has no place to put that dependence.

So the work is not in the proof, it is in the definition that has to exist before the proof can start. Generalise the concept so that it takes the accumulated record as a second parameter — reachability along paths that stay outside the visited set, rather than reachability full stop — and recover the original as the instance where the record is empty. Getting the boundary case right in that definition is where the subtlety concentrates: a path is admissible when its interior avoids the set, and whether the *final* node is allowed to be in the set is a real decision that determines whether the composition laws work at all. This is the general shape of the situation. A local optimization whose effect is "do not redo what has been done" always converts an absolute specification into a relative one, and the vocabulary for saying so has to be built rather than borrowed.

The payoff for building it is that the correctness argument collapses to a small algebra. Once the relativized notion exists, two laws about it carry everything: one saying that processing two groups in sequence, with the second run against a record already enlarged by the first, covers exactly what processing them together would have covered; and one saying that a single step from an unvisited item, with that item added to the record, accounts for exactly what that item reaches. With those in hand, the induction over the loop and the recursive call is bookkeeping. That is the trade worth recognising: effort spent defining the generalised concept and proving a couple of laws about it buys you a program proof that has no cleverness in it, which is much better than a clever proof.

**Source:** [The Craft of Programming](../works/the-craft-of-programming.md) — Section 5.4.1, which starts from a recursive search procedure that adds a node and recurses on its successors, notes that it fails to terminate on a cyclic path, adds the guard that ignores nodes already in the accumulated set, then observes that proving this requires describing the procedure's behaviour when the accumulated set is not initially empty, and therefore introduces paths that avoid a given set (with the final node exempted from the restriction) and the reachability operator relative to such a set, recovering ordinary reachability as the empty-set instance; the two properties then established about that operator — one about splitting a source set into two groups with the second run against an enlarged record, one about a single edge step from a node outside the record — are what the induction on the for statement and the recursive call are discharged from.
