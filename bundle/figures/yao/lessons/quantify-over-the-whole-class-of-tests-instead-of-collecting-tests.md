# Replace a growing checklist of tests with one quantification over every test the checker could run

**Lesson:** When a property has no definition, practice substitutes a battery of checks for it, and the battery grows every time someone finds a case it misses. That regime has three defects that no amount of additional checks repairs. Passing the battery means nothing unless you can show the specific properties it probes are the ones your application actually depends on, which is almost never available. Predicting behavior under a given check tends to be analytically intractable, so confidence rests on accumulated experience rather than argument. And the battery is open-ended by construction: a checker who merely examines the same output in a different order is running a test nobody wrote down, and whether the artifact survives that is simply unknown. The escape is to stop enumerating and quantify. Define the property as indistinguishability from the ideal object by *any* checker drawn from a stated resource class, and the checklist becomes a consequence rather than the definition.

That single move changes what a claim is worth. A component certified against a list is certified for the applications whose needs the list happens to cover; a component that no bounded checker can distinguish from the ideal is usable in every application whose own logic runs inside that bound, including applications not yet invented, because any exploit of the difference would itself be a distinguishing checker. The definition also localizes the argument: instead of analyzing behavior test by test, you argue once about a class. Note what makes the quantification honest rather than vacuous — the checker class must be tied to a real resource limit, and the permitted discrepancy must shrink faster than any bound the checker's own budget can amplify, or "indistinguishable" degenerates into "nobody has looked hard yet."

The strongest confirmation that such a definition is the right one is convergence. If the same class of objects is picked out by an operational criterion (surviving every bounded checker), by a quantitative criterion (its content, measured under the resource bound, being as large as its size permits), and by a structural one, then the definition is not an artifact of any of those vocabularies. Multiple independent characterizations of the same boundary is the pattern to look for whenever you are unsure a new definition carves reality — and the same pattern is what tells you the definition of an interface, a failure model, or an isolation guarantee has captured something instead of encoding one team's checklist.

**Source:** [Theory and Applications of Trapdoor Functions](../works/theory-and-applications-of-trapdoor-functions.md) — the indistinguishability and pseudorandomness sections of Part 1: the critique of selecting a generator by statistical tests (the needed randomness properties can seldom be isolated, and behavior under a given test is usually established only empirically), the definition of perfection as indistinguishability from the truly random ensemble by any bounded witness algorithm, the theorems establishing that this coincides both with passing every polynomial statistical test and with the effective-entropy measure attaining full length, and the later discussion question observing that a sequence unbiased when read forward is not known to remain so when read in reverse.
