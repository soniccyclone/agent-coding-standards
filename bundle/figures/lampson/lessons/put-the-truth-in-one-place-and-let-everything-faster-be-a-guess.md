# Designate exactly one representation as authoritative, optimize it for being checkable rather than for being fast, and let every faster structure be a guess you are allowed to discard

**Lesson:** The most useful structural decision in a system is to split its state into one authoritative account and an arbitrary number of accelerators derived from it. The authoritative account carries correctness and is designed for exactly that: cheap to write, cheap to validate, resistant to being left in a half-state by a crash. An append-only record of the operations applied to an object has all three properties, and it makes the object's current value into something closer to a derived artifact than a primary one. Everything else — the index that turns a name into an identifier, the table that says which blocks are free, the route to a distant node, the type of the object this call site saw last time — exists purely to avoid a search, and is therefore permitted to be wrong. The requirement on a guess is not that it be correct but that its correctness be verifiable before anything irreversible depends on it, and that it be right often enough to pay for the check.

This is a far stronger claim than "use a cache," because it dissolves the anxiety that normally attends derived state. Once you have accepted that the accelerator may be stale, the hard question stops being how to keep it consistent and becomes how to detect that it isn't. The check gets designed first, and the fast structure is free after that. The best version puts the validating information physically adjacent to the data it guards, so confirming a guess costs nothing extra on the path that was already going to touch the data. A guess that fails is not a bug; it is a slow path, and the truth can always be rebuilt by exhaustive search — unacceptably slow but always available, which is precisely why the guesses are allowed to exist. The discipline extends to distributed state, where nobody can have a consistent view anyway: each participant guesses at global conditions, knows for certain only the local facts it owns, and behaves acceptably because the guesses are usually good and the errors are detectable.

The same split explains why the only logically necessary correctness check in a layered system sits at the very top. If you want to know that data arrived intact, you compare what is present at the destination against what was present at the source; no amount of checking at intermediate hops establishes that, because damage can occur between the checks, in the buffers, anywhere. Conversely, once the end check exists, every intermediate check becomes unnecessary — its sole function is reducing how much work must be redone when the end check fails. That reclassification is liberating and clarifying at once: it tells you that intermediate error handling is a performance parameter you may tune or omit at will, and it tells you that a system with elaborate hop-by-hop guarantees and no end check is not reliable, merely expensive. It also warns you what the end-to-end position costs, namely that you need a cheap test for success and that a system built this way can pass every test and still collapse under load, because all the redoing only shows up when errors become frequent.

The complement to a truthful log is atomicity: an action that either happened or didn't, so recovery never has to reason about intermediate states. The cheap way to get it is to make the recorded operations replayable — applying one twice must be indistinguishable from applying it once — and to require that each recorded operation be a genuine function of its arguments, with no dependence on ambient state and no effects outside the object it belongs to. That constraint is the whole trick. It converts a history into something you can rerun, which is what makes both recovery and derivation-from-truth work at all. A programmer who has internalized this reaches for an operation log and a small set of functional update primitives early, treats every index and cache in the system as expendable, and can answer the question "what in this system is allowed to be wrong?" precisely, which is a question most systems cannot answer at all.
