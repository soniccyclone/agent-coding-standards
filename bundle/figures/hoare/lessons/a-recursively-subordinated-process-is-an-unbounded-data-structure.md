# A recursively subordinated process and an unbounded data structure are one construction, held together by local naming

**Lesson:** A component that retains one item and delegates everything else to a privately created copy of itself is, depending only on which vocabulary you are speaking, a recursive data structure or a recursive process. These are not analogues of each other; they are the same construction described twice. Each level holds a single element and declares a fresh subordinate to hold the rest; the subordinate presents exactly the interface its parent presents; the whole thing terminates because the outermost client eventually stops asking. Read one way that is a linked structure, read another it is a recursion whose activation records happen to persist and answer questions. The unification is worth having because arguments developed for one apply to the other — reasoning about layout and reasoning about who is waiting on whom become the same reasoning.

The construction stands or falls on the naming discipline. A subordinate is reachable only through a name its immediate parent knows, and that name is concealed from everything outside, so a grandparent can neither address a grandchild nor discover that one exists. That concealment is what makes arbitrarily deep nesting safe rather than merely possible: at every level the vocabulary in play is small and local, and depth costs nothing conceptually because no level can see past its own subordinate. The accompanying rule that a repeated name renders the outer bearer inaccessible is the ordinary shadowing rule of scoped languages, and its appearance here is not coincidence — hiding is precisely what converts a name from an address into a local variable.

Two consequences are worth taking to real designs. Because each level is a full component rather than a passive record, a level may answer a query itself instead of passing it on, and it may hold more than one subordinate. That is the entire difference between an unbounded list and a search tree: each level routes to one of two subordinates instead of the only one, and the external interface does not change by a single character. Internal structure is therefore invisible to clients by construction rather than by convention. And because levels are components, the cost model is not a record's: a query travels level by level and every level does work, so the depth of the structure is the latency of a lookup. Stated that way, the argument for a shape that halves rather than decrements is immediate and concrete, instead of an asymptotic claim someone has to be talked into.
