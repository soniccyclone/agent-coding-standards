# Declare each participant's read and write sets; their disjointness is what licenses moving code across the concurrency boundary

**Lesson:** Attach to every concurrent participant two declared sets: the state it may modify and the state it may consult, with the first necessarily contained in the second. Then impose one condition on any two participants that will run together — neither one's write set may intersect the other's read set. The condition is checkable from declarations alone, before anything runs, and it is the sole thing standing between you and having to reason about interleaving. It is not a coding convention or a review checklist item; it is a well-formedness rule on the composition, and a composition violating it is not a program with a race, it is not a program.

What the condition buys is stated most usefully as a permission to move code. Under it, an update performed before participants diverge and the same update performed inside one of them afterwards are indistinguishable; a condition tested before the split and tested inside a branch after it are indistinguishable; two participants' initial updates may be merged into one simultaneous update or left separate. In other words, the boundary between "sequential setup" and "concurrent region" stops being semantically significant, and code may be pushed across it in either direction to suit efficiency or clarity. Implementations inherit the same freedom: sequences of updates in different participants may be executed together or in any interleaving whatever without altering a single observable action. That is the real content of the guarantee — not that races have been outlawed by decree, but that a specific list of rewritings has become sound.

Two things to carry forward. The two sets have to be separately declared, because reading and writing are not symmetric: many participants may read what none writes, and the condition constrains write-against-read rather than read-against-read, which is exactly what permits wide sharing of immutable state at no cost. And notice which way the dependency runs. The declarations are not documentation extracted from the code; the code is admissible only if it stays inside them. A system whose participants' effects can only be discovered by reading their bodies has no way to check the condition at all, which is why the discipline has to be part of how a participant is declared rather than something inferred about it afterwards.

**Source:** [Communicating Sequential Processes](../works/communicating-sequential-processes-book.md) — the laws subsection of the assignment section in the sequential processes chapter, which introduces into a process's alphabet the set of variables it may assign and the set it may access, requires the former to be contained in the latter, stipulates for parallel composition that each operand's assigned variables be disjoint from the other's accessed variables, and then gives the laws permitting an assignment to be moved across the parallel split, two operands' initial assignments to be merged into one multiple assignment, and a conditional's test to be evaluated on either side of the split — with the accompanying remark that under the restriction an implementation may carry out sequences of assignments together or in any interleaving without any difference to the externally observable actions.
