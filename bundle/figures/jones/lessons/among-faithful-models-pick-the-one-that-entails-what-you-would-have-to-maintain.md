# Among models that describe the same thing, pick the one that entails the properties you would otherwise have to maintain

**Lesson:** A concept usually admits more than one faithful description, and the descriptions are not interchangeable even though they denote the same thing. Take a notion of "these two are the same for our purposes". The definitional description is a collection of the pairs currently held to be equivalent, plus the requirement that it be closed under reflexivity, symmetry and transitivity. The alternative is a division of the whole population into groups with nothing in common. Both capture exactly the same object; they differ entirely in where the closure requirement lives. In the first it is an obligation you carry — every insertion has to chase down the consequences, and every reader has to be told that the raw collection is not the real content. In the second the closure is not an obligation at all: reflexivity and symmetry hold because membership in a group is symmetric, and transitivity holds because the groups do not overlap. Nothing enforces it, so nothing can fail to enforce it.

The general instruction is to treat model choice as a search for entailment rather than a search for accuracy. Accuracy is a filter, not a criterion — several candidates will pass it. What separates them is which of the properties you care about become theorems of the structure and which remain conditions someone has to keep true. Every property that becomes structural disappears from the invariant, from each operation's obligations, and from the list of things a maintainer can break.

There is a signal that tells you when you have found the good model, and it is worth watching for because it is unambiguous. The operations get short. If joining two things into one equivalence is "replace the two groups containing them with their union", the definition is one line, obviously terminating, and obviously monotone in the sense that an equivalence once recorded is never lost — a safety property you can read off the description instead of proving. When an operation on a candidate model stays complicated no matter how you write it, the complication is usually not intrinsic to the problem; it is the model paying rent on a property it fails to entail.

Two cautions. The good model rarely eliminates the invariant entirely — the partition still has to be stated to be a partition — so the goal is to shrink what the invariant carries, not to expect zero. And a model chosen this way is a description, not a plan: the fact that the structure makes a property free says nothing about whether an implementation built the same shape would perform acceptably, which is a separate decision made later against a different criterion.

**Source:** [Software Development: A Rigorous Approach](../works/software-development-a-rigorous-approach.md) — chapter 8's "Recording Equivalence Relations" section: the review of reflexivity, symmetry and transitivity and the observation that a relation is exactly the set of pairs satisfying it; the introduction of the alternative view of an equivalence relation as a disjoint partitioning of the base set, with the explicit remark that this model guarantees the three required properties, reflexivity and symmetry obviously and transitivity because the subsets are disjoint; the note that the model immediately suggests the specification, since making two elements equivalent is achieved by uniting the sets containing them; the resulting one-line post-conditions for the initialize, equate and test operations; the accompanying data type invariant stating that the state is a partition of the base set; and the closing observation that one can see by inspection of the specification that an equivalence once entered is never destroyed.
