# Carve a description into units for the reader's sake, and depend on what each unit promised rather than on how it was written

**Lesson:** Packaging a piece of what a system holds together with the operations over it buys one specific and valuable thing: you can rework its innards later without touching anything that used it, so long as the answers visible from outside are unchanged. Note how narrow that guarantee is — it insulates against changes to internal detail and against nothing else. Change the visible behaviour and every user is affected, correctly so. Note also what the guarantee is not: the boundaries you drew to get it are not a plan for how the built system should be carved. The implementation may well have to be divided differently to perform acceptably, and treating the description's units as a construction blueprint is how a description begins constraining decisions it was never entitled to constrain.

The criterion for what deserves to be its own unit needs stating, because the insulation is pleasant enough that the temptation is to make everything one — at which point nothing is insulated from anything and you have only added ceremony. Two questions do the work. Is it likely to be used again elsewhere? And do its operations form a coherent body — is there anything to say about how they relate to one another, any properties worth establishing once and citing thereafter? Something that fails both is not a concept; it is a field of a record wearing a costume. The second question is the more discriminating of the two, and it is the same question as whether a small theory of the thing can be written, which is a test you can actually apply before committing.

The mechanism that makes such a boundary real at description level is worth spelling out, because it is not obvious and it generalizes. A state-changing operation cannot be invoked inside a logical statement, so what a dependent description actually reuses is the operation's stated conditions, applied to whichever part of the larger structure is relevant. The dependency is therefore on what was promised and never on how the promise was arranged internally — which is exactly why the insulation is genuine rather than nominal, and why reformulating everything behind the boundary leaves the dependents untouched. Depend on the promise, not the definition, and the boundary survives. One last practical note in the same spirit: long descriptions do need natural-language help, and the most effective form of that help is not inline remarks but exactly this decomposition into named concepts with prose introducing each one, which is the same discipline serving comprehension instead of change.
