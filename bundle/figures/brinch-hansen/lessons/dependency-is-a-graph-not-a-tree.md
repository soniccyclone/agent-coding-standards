# Dependency among components is a graph, not a tree, so state it in the source and forbid the cycles

**Lesson:** Block structure gives you visibility as a side effect of nesting: whatever encloses you, you can see. That model is wrong about how real systems are shaped. In a working system two unrelated components frequently need the same arbitrator, and a component frequently needs nothing at all from most of what textually surrounds it, so the true relation is a directed graph with sharing and with plenty of absent edges. Inheriting visibility from nesting therefore grants access nobody asked for while making legitimate sharing awkward, and the reader loses the ability to know what a component depends on by reading it. The alternative is to make dependency an explicit declaration: a component names the other components it may use, receives them when it is created, and can reach nothing else.

Written down that way, the graph becomes an object of reasoning rather than an emergent property, and the one global constraint worth imposing on it is acyclicity. The immediate reason is deadlock: any construct that excludes others while it runs will hang if a chain of calls comes back around to it, so a cycle in the dependency graph is a latent deadlock, and forbidding cycles at compile time forbids the whole class. The deeper reason is that an ordering makes induction available. Freedom from indefinite waiting can be argued level by level, starting where nothing is depended upon and working outward, and the same technique settles resource allocation when requests move in one direction through the ordering and releases in the other. Ordering also has a mundane engineering use: putting the fastest physical resources lowest tends to fall out of the same layout.

Two cautions keep this honest. An ordering is necessary rather than sufficient — a hierarchy of components connected through finite intermediate storage can still wedge, because full and empty capacity in different parts of the graph can conspire, so the proof has to be done rather than assumed from the picture. And the direction of naming matters as much as the direction of dependency: when only the caller names the callee, a server never learns the identity of anything that uses it, which is what makes a component reusable in a system its author never imagined.
