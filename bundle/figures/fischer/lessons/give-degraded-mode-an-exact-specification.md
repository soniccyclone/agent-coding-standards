# A weaker guarantee still deserves an exact one: specify degraded operation, do not merely apologize for it

**Lesson:** There are two very different things people mean by giving up a strong consistency guarantee. One is vagueness: the system keeps running while partitioned, results are "approximate", and what a read may return during failure is left to the reader's imagination and the implementer's mood. The other is a different exact guarantee, stated over a different reference frame. Instead of defining correctness against an imagined global serial order that partitioned nodes cannot construct, define it against the communication that demonstrably occurred: an item is present in a node's view precisely when that node has learned of its insertion and has not learned of its deletion, where "has learned of" is the causal reachability relation generated by local ordering and by each message linking its send to its receive. That is a complete specification. It has no failure clause, because failure is not an exception to it — a partition simply makes the causal relation sparser, and the specification keeps saying exactly what each node sees.

Why the reframing is legitimate: partition tolerance and a single global order are in genuine conflict, since availability requires every live replica to keep accepting updates while serializability requires at most one to. Faced with a real conflict, the productive response is not to keep the unattainable ideal as the nominal spec and treat every deviation as an incident, but to move the reference frame to something the system can actually be held to. The weaker property is then provable, and — importantly — it degrades legibly: a user can predict what they will see from what they know about which messages got through, and a system that has been fully connected recently looks like the strong system.

The programmer who works this way treats "eventually consistent" as an unfinished sentence. What, exactly, is guaranteed at each moment, as a function of what has actually propagated? What is the observable difference between healthy and partitioned operation? If those questions have crisp answers, the weaker model is engineering. If they do not, the weakening was not a design decision, it was an abdication — and the resulting system cannot be reasoned about at all, which is a worse outcome than either the strong guarantee or an honestly stated weak one.

**Source:** [Sacrificing Serializability to Attain High Availability of Data in an Unreliable Network](../works/sacrificing-serializability-to-attain-high-availability-of-data.md) — the framing of availability against serializability, and the correctness conditions defined over the partial order of local and message-linked events so that the semantics remain fully determined under partial failure.
