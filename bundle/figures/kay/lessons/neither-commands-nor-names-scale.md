# Neither commands nor names scale, so let modules notice conditions and carry a runnable model of what they need

**Lesson:** Two mechanisms that work perfectly in a small system fail as it grows, and they fail for the same reason: both require the caller to know things it cannot know at scale. Directing a component to perform an action means the sender must have decided who should act and when, which becomes untenable once the population of components is large, changing, or partly foreign. Referring to a component by name means someone must already agree on the name, and across a large enough collection the same capability appears under many names while the same name means different things, so lookup by name degenerates into a social problem. The alternative that does scale is inversion: each component watches for the conditions under which its own contribution is useful, decides for itself, and changes only itself. Nobody has to know who will respond, and the set of responders may change without any sender being updated. The property this buys is that the system's coordination cost stops growing with the number of participants that need to be told.

For that to be more than an ideal, a component needs to state precisely what circumstances it is interested in, and here the same statement can be made to do several jobs at once. Let a component carry a runnable model of the environment it expects — not a type signature, which says almost nothing about meaning, but a small executable characterization of the behavior it needs and the tolerance it will accept. That model is simultaneously the basis on which the system can automatically detect the conditions the component cares about, the stand-in that lets the component be exercised and debugged with nothing else present, the default to fall back on when nothing better is available, and the thing a matcher compares against the promises of candidate providers when it goes looking for a real one. Matching by sampled behavior against a stated tolerance is inexact and probabilistic, which feels unsatisfying next to a name lookup, but it is answering a question a name lookup cannot even pose.

There is a failure mode to watch for, and it is the one that historically consumed the purity of object systems: a general substrate can always be used to simulate the specific mechanism it was meant to replace. Just as objects get reduced to containers for fields with getters and setters, a notice-and-react architecture can be used to fake direct calls — one publisher, one known subscriber, an immediate reply — which restores every scaling problem while leaving the architecture nominally intact. Whether the style stays pure enough to make a real difference is not settled by the mechanism; it is settled by whether people are willing to give up knowing exactly who will act.
