# Redundancy is a claim about the current whole, not a property of the part, so growing the system elsewhere can silently make a removable thing load-bearing

Church defines a rule of inference as independent when there is some theorem the system cannot prove without it, and then drops a warning in a footnote that is easy to read past: a rule which is not independent may become independent once further axioms are adjoined. Nothing about the rule changed. What changed is that the system now proves more things, so the demand placed on the rule's substitutes grew — they must now reproduce it across a larger population of premises, and the derivation that used to cover every case need not cover the new ones. Independence was never a property of the rule. It was a relation between the rule and everything else, evaluated at one moment.

The reason this is not a curiosity is that redundancy claims are always universally quantified over the system's current reach, and additions to the system extend the range of quantification. "This is covered by that" means "for every situation reachable today, that handles it." Enlarge what is reachable and the sentence is not weakened, it is falsified — by a change that happens somewhere else entirely and mentions neither party. Church is alert to this in the other direction too: when he proves the rule of substitution indispensable by a formula-length argument, he pauses to note that the argument survives adjoining any finite number of further axioms. He is distinguishing arguments that are robust under growth from arguments that hold only against the system as it stands, and he does it as a matter of routine.

Engineers make redundancy claims constantly and almost never record their scope. A helper is deleted because the general path handles every case it handled. A polyfill is dropped because every supported runtime has the feature. A compatibility branch is removed because no live client sends the old format. A test is deleted as subsumed by a broader one. A defensive check is removed because the caller already validates. A retry wrapper is called pure optimization because the underlying call has never failed at current volume. Each of those is true, and each is true of the system that existed when it was said. Add a target platform, a new caller, a new field, a new region, a code path that reaches the same function by a different route, and the deleted thing was the thing that would have covered it. The failure does not appear in the diff that added the new capability, because that diff is about the new capability. It appears later, as a gap nobody put there.

Two things follow. First, when you justify a removal, write down the quantifier — not "the general path covers this" but "the general path covers this for the four input shapes we accept and the two runtimes we build for." A justification with its scope attached is a thing a future change can be checked against; a justification without one is folklore that decays invisibly. Second, prefer the arguments that survive growth. Church's length argument for substitution beats his truth-table arguments for the axioms precisely because it does not depend on the system's exact contents, and he says so. In engineering the analogue is that "this is unreachable because the type makes it unconstructible" outlives "this is unreachable because nothing currently calls it," and "this check is redundant because the same function performs it" outlives "this check is redundant because our callers happen to validate first." The stronger justification usually costs a little restructuring and buys immunity from every future change made by someone who never read your reasoning.

**Source:** [Introduction to Mathematical Logic](../works/introduction-to-mathematical-logic.md) — the section on independence, its definition of an independent axiom or rule as one without which some theorem cannot be proved, the accompanying footnote observing that a rule of inference not previously independent may become independent when additional axioms are adjoined to the system, and Church's remark that his length-based proof of the independence of the rule of substitution continues to hold after the adjunction of any finite number of additional axioms.
