# One-pass admission with no backtracking is correct exactly when rejection is permanent and every violation has a finite witness — check both before you write the loop

Church builds a maximal consistent collection of formulas by the crudest possible method: enumerate all candidates, take each in turn, admit it if it is compatible with everything admitted so far, otherwise discard it forever. One pass, no revisiting, no backtracking, and the result is provably both consistent and maximal. What makes such a naive loop correct is not obvious, and his proof turns on exactly two structural facts that he establishes rather than assumes.

The first is that a violation can only ever involve finitely many members. If the final collection were inconsistent, some finite handful of its members would already be inconsistent; each of those was admitted at some finite stage; so the largest of those stages was already inconsistent, contradicting the stage-by-stage argument. This is what lets an infinite limit inherit a property that was only ever checked on finite prefixes. The second is that compatibility only gets harder as the collection grows. Anything compatible with the final result was necessarily compatible with the smaller collection present when its turn came, so it was admitted then — which is precisely why nothing was missed and the result is maximal. Neither fact is decoration. Drop the first and the limit can violate a property every stage satisfied. Drop the second and a candidate rejected early might have been admissible later, so a single pass leaves value on the table and the greedy answer is not maximal.

The pattern generalizes to every accept-or-discard loop over a stream, and the two conditions are the ones worth checking before writing it. Rejection must be permanent in the sense that the constraint tightens monotonically: adding items never makes a previously-blocked item admissible. Violations must be finitely witnessed: whenever the accumulated whole is bad, some bounded part of it is already bad. When both hold, you get a great deal — the check can be incremental, the state you carry is whatever the check needs, nothing needs to be reconsidered, and the result at any point is valid rather than merely on its way to valid.

Most incremental validation lives or dies on these. A schema validator streaming over a document is fine because malformedness is always witnessed by a bounded region. Accumulating constraints in a solver, admitting each if it does not conflict, is fine for the same reason. Appending to a log with an invariant checked against the tail works when the invariant is finitely witnessed and fails silently when it is not — "no duplicate identifiers" has a two-element witness and is safe; "every started transaction eventually commits" has no finite witness at all, and a per-append check will pass forever on a stream that violates it. The monotonicity condition fails in a different and sneakier way: a resource-allocation admission check where a later arrival releases capacity, or a rule engine where adding a rule can resolve a conflict rather than create one. In both cases the one-pass loop is still perfectly deterministic, still terminates, and quietly returns something that is not maximal, which is the worst kind of wrong because nothing signals it.

So the practice is to state the two properties out loud when reaching for a streaming or greedy accept/discard design, and to treat their failure as a design finding rather than an inconvenience. If violations lack finite witnesses, incremental checking is not merely weak, it is checking a different property, and you need a separate global pass or a different invariant that does have finite witnesses. If admissibility is not monotone, you need either backtracking, a second pass, or a reordering of the stream that restores monotonicity — and noticing which of those three you need is much cheaper before the loop is written than after someone reports that the output is missing an item that clearly should have fit.

**Source:** [Introduction to Mathematical Logic](../works/introduction-to-mathematical-logic.md) — the proof of the lemma extending a consistent class of formulas to a maximal consistent one: the stage-by-stage construction admitting each formula of a fixed enumeration if it is consistent with the current stage, the argument that the union of the stages is consistent because an inconsistency would involve finitely many formulas all present at some single finite stage, and the argument that the union is maximal because any formula consistent with the union was consistent with the stage at which it was considered and hence was admitted there.
