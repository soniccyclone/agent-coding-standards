description: The core public statement of DCI (Data, Context, Interaction), written with Jim Coplien as a companion to their more formal 2009 conference paper on the same material. Argues that mainstream class-based OOP conflates two things that should stay separate — the stable data structure of objects and the transient roles those objects play in a given runtime interaction — and that code should be organized around end-user mental models of interaction, not around class taxonomies. This is the piece that carried Reenskaug's original MVC-era "objects as mental models" argument into a full architectural paradigm.
