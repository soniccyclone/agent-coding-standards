# Measure a thing by the shortest program that produces it, not by how much of it there is

**Lesson:** The obvious way to say how big something is counts what it contains — bytes, records, lines, states. The more useful way asks what is the smallest description from which the whole thing can be mechanically regenerated. Those two numbers can be arbitrarily far apart, and the gap is exactly the redundancy: everything in the artifact that was implied by something else in it rather than independently chosen. A million rows generated by a rule are a rule, not a million facts; a thousand-line module that is four decisions and their consequences is four decisions. Sizing by extent flatters bulk and hides structure, while sizing by shortest generator reports what actually had to be decided.

Two things make this a working habit rather than a slogan. First, the description has to be *executable* — a generator, not a gesture at one — which forces honesty. Claiming a system is "really quite simple underneath" means nothing until you can name the program that emits it, and the attempt usually reveals which parts genuinely are irreducible and which were repetition you had stopped seeing. Second, it is inherently relative: the same measure with a second object supplied as input gives the cost of getting from one thing to the other, which is the real question in most engineering. How much new information is in this release, this fork, this subclass, given what already exists? If the answer is small, the artifact should be small too, and if the artifact is large anyway, it is carrying weight that nothing required.

The generalization worth keeping is that irregularity is expensive and regularity is free. Anything patterned compresses, so the cost of a design is dominated by its exceptions, its special cases, its unprincipled choices — the parts a generator cannot fold into a rule and must therefore spell out one by one. That reverses the usual accounting, where the special cases look cheap because each is only a few lines. Under the shortest-generator measure each one is a permanent addition to the smallest possible description of the system, and it never gets any cheaper.

**Source:** [Three Approaches to the Quantitative Definition of Information](../works/three-approaches-to-the-quantitative-definition-of-information.md) — the third, algorithmic approach of §3, where the relative complexity of an object given another is defined as the minimal length of a program that produces the first from the second, and the unconditional complexity is recovered as the special case of producing it from nothing.
