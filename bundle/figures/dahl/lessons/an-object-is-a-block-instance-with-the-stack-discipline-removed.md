# Reach a new paradigm by lifting a restriction off an existing primitive, not by adding one

**Lesson:** The object was not invented as a new kind of thing. It was arrived at by noticing that the ALGOL block already had every property wanted from an object, and that only one accident of implementation stood in the way: block activations were required to be born and to die in the nesting order of their entry. A block text is already a pattern describing local data together with the actions over that data; entering it already generates an instance holding storage for those locals; several instances of the same text can already coexist, as recursion demonstrates. Take away the rule that an instance must vanish when control leaves it, allow instances to be named and pointed at, and the block text becomes a classification of the instances that conform to it. Nothing was added to reach the object except permission for a block instance to outlive the activation that created it and to be referenced from elsewhere.

This matters because of what it buys in structural economy. The whole edifice built on top of the change inherits the semantics of a construct that was already precisely defined and already understood by every user of the base language: scope, locality of names, parameter transmission, the meaning of a declaration. The organizing question of the corpus this figure sits in is how many irreducible constructs a formalism actually needs, and the answer here is that classes, objects, and eventually subclasses cost nearly nothing in new primitives because they are expressed as consequences of the block. The visible sign of this discipline is that program executions before the change formed a simple dynamically nested structure, and after it form arbitrary linked structures, with the *same* rules describing both. The stack case did not become a special case; it became the situation where nothing has detached.

Compare the alternative route, which is what most systems take: introduce a new record or object construct alongside the existing block, with its own scope rules, its own initialization story, its own lifetime story, and then spend years reconciling the two. Every reconciliation is a place where a programmer's intuition from one construct misfires in the other. The Simula route left one structuring mechanism and one set of intuitions to carry.

A programmer who believes this looks at any desired new feature by first asking which existing primitive is already almost the feature, and what artificial constraint on it is doing the blocking. Constraints that exist for implementation convenience, particularly ones inherited from a storage strategy such as a stack, are the highest-value targets, because removing one tends to generalize the construct in several directions at once rather than in the single direction that motivated the change. The corresponding discipline is to state the new freedom as precisely as the old restriction was stated, since a lifted constraint that is only informally described costs back everything it saved.
