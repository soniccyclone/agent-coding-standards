# You can only offer to rewind what you mediate, so the undo obligation lands on whoever owns the effect

**Lesson:** Any mechanism that explores a possibility and then abandons it — search, speculation, transactions, optimistic concurrency, a debugger that steps backwards — is promising to restore a state that other code was busy modifying. The promise is only keepable to the extent that the mechanism sits between that code and the state it modifies. There is no way to write a general undo; there is only the sum of the specific undos contributed by every operation capable of leaving a mark. The correct architectural reading is that rewinding is not a service the control layer provides, it is an obligation the control layer distributes, and every effecting operation has to pay its share.

The concrete form is worth learning because it recurs. At the moment an operation is about to change something, it records what the old state was and manufactures a small piece of work that would put it back. That piece of work is then inserted into the abandonment path so that it runs before whatever abandonment was already pending, and after running it hands control on to that pending work rather than stopping. Effects therefore compose into a chain of restorations that unwinds in exactly the reverse of the order the effects occurred, and it does so without any component keeping a global log or knowing how many effects preceded it — each one only needs to know its own old value and the one abandonment step it displaced. The cost is proportional to effects performed, not to the size of the state.

The load-bearing precondition is total mediation, and this is where such designs fail in practice. Every state change has to route through the layer that installs these restorations. One write that goes around it — an operation that reaches the store directly, a call into a foreign component, a message already sent, a file already flushed — is a change the mechanism does not know happened and cannot reverse, and its existence is not detectable from inside. So the honest question to ask of any speculate-and-retry design is not whether the rollback logic is correct but what the complete inventory of effects is and whether the layer genuinely sits in front of all of them. If the inventory is open-ended, the design is not sound and no amount of care in the rollback path will make it so.

There is a useful converse. State that is created rather than modified, and whose lifetime is bounded by the abandoned attempt, needs no restoration at all, because abandoning the attempt already discards it. That observation is what makes it worth structuring things so that speculative work builds fresh state rather than editing existing state — not for purity, but because it moves entries off the inventory that would otherwise each need a hand-written reversal. The set of operations that need undo logic is exactly the set that mutates something outliving the attempt, and shrinking that set is the cheapest way to make the whole mechanism trustworthy.

**Source:** [Structure and Interpretation of Computer Programs](../works/structure-and-interpretation-of-computer-programs.md) — chapter 4 section 4.3.3, the treatment of assignment in the nondeterministic evaluator: the general statement that when a side-effecting operation occurs on a branch of the process it may be necessary to undo the effect before a new choice is made, and that this is accomplished by having the side-effecting operation itself produce an abandonment step that reverses the effect and then propagates the abandonment; the assignment execution procedure, which on success saves the variable's previous value, performs the write, and hands forward a replacement abandonment step that restores the previous value and then invokes the abandonment step it intercepted; the accompanying note in section 4.3.2 that the parser's use of destructive update of the unparsed-input variable only works because the evaluator undoes such updates when it backtracks; and the footnote observing that definitions need no such treatment because internal definitions are scanned out beforehand.
