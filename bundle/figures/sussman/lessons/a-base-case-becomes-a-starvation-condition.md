# Replace control flow with a topology and a base case becomes a starvation condition, so recursion has to be built as growth gated on arrival

**Lesson:** A model in which a program is a fixed arrangement of connected machines rather than a sequence of steps appears at first to be unable to express unbounded computation. The arrangement is finite and exists before anything runs, so a definition that mentions itself would have to expand without limit while being constructed, and there is no step counter anywhere to stop it. The resolution is to make one thing in the system lazy — not the computation of values, but the construction of structure. A composite machine holds a recipe for its own interior and refuses to run that recipe until at least one of the places it watches actually contains something, and then runs it exactly once. A self-referential definition is now a potentially infinite object whose expansion is purchased one level at a time by the arrival of information, and how deep it goes is a runtime fact about what was learned rather than a static fact about the text.

What follows is a change in the character of termination that is worth holding onto, because it transfers to every system of this shape. There is no branch that fails to be taken, because there are no branches; the recursive instance is unconditionally present in the description and is never forbidden to exist. It simply never receives anything, because the test that decides whether the computation is finished is wired so that when the answer is yes, the places feeding the next level stay empty. The base case has become a starvation condition. So when you are convincing yourself that a construction of this kind terminates, do not look for the guard that stops execution — look for the supply that stops, and trace which places remain empty forever. Any system where you have traded control flow for a topology has this property: dataflow graphs, actor arrangements, reactive dependency networks, build systems, spreadsheet-like models. In all of them, unbounded structure is safe exactly to the degree that starvation is reachable, and a "loop that never ends" is a place that keeps getting fed.

Two obligations come with gating growth on arrival, and both are easy to get wrong in the same direction. First, growth must be idempotent, because arrivals repeat: information at a watched place will be strengthened many times over the life of the computation, and if each arrival triggers construction, the structure grows with the number of refinements rather than with the depth of the problem. Second, the gate must fire when *any* watched place has become non-empty, not when all of them are complete. Waiting for everything is the intuitive condition and it silently reintroduces the wait-for-the-whole-value behaviour that a partial-information architecture exists to avoid — a level that could already start deducing something useful from one fragment would sit idle instead. Notice also the asymmetry this creates, since it is informative: the computation itself can be entirely eager, with every machine deducing everything it can as soon as it can, while the one genuinely demand-driven thing in the system is how much of the system exists.

**Source:** [The Art of the Propagator](../works/the-art-of-the-propagator.md) — the iterative square-root example and its accompanying machinery, where a machine acts only when it has inputs worth working on, a composite machine constructs its body on demand and only once and only if some watched place is non-empty, the recursive instance is written unconditionally and is starved of inputs by switches driven by the good-enough test, and the closing section's remark that the networks otherwise resemble applicative order in that every machine computes every deduction it can as early as possible.
