# If updates only ever add information, order stops mattering — and the single operation that takes information away costs you that freedom everywhere

**Lesson:** Constrain every update so that it can only strengthen what is known at a shared location, never replace or weaken it, and a remarkable amount of machinery becomes unnecessary. Nobody can be harmed by observing a location early, because what they see will still be true later. A step that runs twice does no damage, because the second run contributes nothing new. Two steps that run in either order reach the same place, because the outcome is determined by the set of contributions rather than their sequence. Consequently there is no need for a global schedule, no need for a distinguished coordinator, and no need for time to advance at the same rate in different regions: the only things requiring mutual exclusion are the individual shared locations and the lists of who is watching them. The structure is genuinely spatial rather than sequential, and that is a consequence of the monotonicity constraint rather than an independent design choice.

The instructive half is what happens when one operation breaks the rule. Add a facility for withdrawing belief in an assumption — a genuinely useful facility, since it lets you explore what follows without some premise — and you have introduced an update that removes information. Every conclusion anywhere that rested on that premise may now be wrong, and nothing local can tell you which conclusions those are, so the only correct response available is to wake every participant in the entire system and let them re-derive. One operation, and the property that justified the whole architecture is gone for the duration. The authors of the system name the symptom precisely: a change of this kind travels instantly through the entire structure with no respect for the structure's own shape, which is exactly the action-at-a-distance that monotonicity had eliminated, and they identify it as the source of the crudeness in that part of their design.

The transferable rule is to inventory your retractions. In any system where correctness currently follows from updates being cumulative — a cache that only fills, a log that only appends, a set of facts that only grows, a lattice that only ascends — the operations that shrink the state are not just a few more cases to handle. Each one is a global barrier, and the cost is not paid where the retraction is implemented but everywhere that depended on never needing to be told. Which does not mean never retract; it means price the retraction honestly, and look hard for a formulation in which the thing you wanted is expressed as an addition instead — recording a new stronger fact, adding a scope marker, contributing a further constraint — because a design with zero retractions is not merely tidier, it is a different kind of system.

**Source:** [The Art of the Propagator](../works/the-art-of-the-propagator.md) — the cell implementation, whose only sanctioned mutation is the addition of information and which notifies watchers solely when the content actually strengthened; the closing discussion of time, which argues that because the structure is space and there is no action at a distance there is no reason for time to pass uniformly across it, with only cells and neighbour sets needing synchronization; and the worldview machinery, where the authors note that manually changing which premises are believed violates the monotonicity assumption, forces the conservative measure of alerting every propagator indiscriminately, and explains the resulting awkwardness as changes travelling instantly through the whole network without respect for its structure.
