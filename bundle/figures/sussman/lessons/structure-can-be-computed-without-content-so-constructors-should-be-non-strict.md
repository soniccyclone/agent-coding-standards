# Structure can be computed without content, which is why constructors are the things worth making non-strict

**Lesson:** Whether an argument is evaluated before a procedure's body begins is usually discussed as a property of a whole language, one setting for everything. It is more useful to treat it as a property of each argument of each procedure. A procedure is strict in an argument if the value must exist before the body runs, and non-strict if the body may begin without it, and there is no reason for these to be uniform: a language can be strict everywhere, non-strict everywhere for compound procedures while its primitives insist on values, or expose the choice per parameter and let the definition say which of its inputs it needs and which it merely mentions. Once you see it that way, "is this language lazy" stops being the question and "which of these parameters does this procedure actually need the value of" starts being it — a question with a determinate answer that the author knows and the type of the procedure usually does not record.

The immediate payoff is that a non-strict argument may be one that has no value at all — divergent, erroneous, expensive — as long as the path taken does not need it. That turns some things that could only be language constructs into ordinary procedures, since what makes a conditional-like form special is exactly that it declines to evaluate one of its parts. The cost is real too: a procedure that is non-strict in an argument the caller expected to be evaluated will not perform the effects the caller was counting on, which is why laziness and side effects together produce reasoning nobody can follow.

The deep case, though, is the one that generalizes furthest: the most valuable thing to make non-strict is not a control construct but a *constructor*. Building a compound value out of parts, and then working with the compound, does not in general require knowing what the parts are. You can ask how long a list is without knowing a single element. You can traverse, count, reverse, and index into a structure whose contents are entirely unknown, because those operations are functions of the shape and the shape was determined by the construction, not by the values placed inside. So a non-strict constructor cleanly separates the schedule on which structure is computed from the schedule on which content is, and lets the second lag arbitrarily far behind — including forever, for parts never reached.

That separation is what makes unbounded structures ordinary rather than exotic. If the constructor does not demand its parts, a structure may be described as containing itself and the description terminates, with each layer materialized only when something reaches for it. Nothing about this is special to lists or to any particular data type; it follows from the observation that structural operations do not read content. When you find yourself unable to express a shape because building it would require producing everything in it, the question to ask is whether your construction step is demanding values it never inspects.
