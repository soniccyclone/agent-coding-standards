# A layer meant to be shared by everything must be low in concept count, not close to the machine — those are different kinds of low

**Lesson:** The economics of a shared intermediate layer are irresistible on paper. With several sources and several targets, connecting each source to each target takes a number of connectors that grows as their product, while routing everything through one common representation makes it grow as their sum. The idea keeps getting attempted and keeps failing, and the failure has a consistent cause worth extracting: designers hear "the layer should be low-level" and build something that resembles a machine. Resembling a machine is the opposite of what the position requires, because a machine's shape encodes that machine's particular commitments — its registers, its addressing, its calling arrangements — and those commitments are exactly what the other targets do not share and what the sources never expressed. A representation that looks like hardware has smuggled one target into a place that was supposed to be neutral, and every other target then has to undo it.

The disambiguation is that "low" names two unrelated properties. One is how few distinct concepts a notation has; the other is how closely it resembles the eventual execution substrate. A shared waist needs the first and is ruined by the second, so the target to aim for is the smallest set of concepts from which every source language's control arrangements and naming arrangements can be assembled — one way to transfer control while carrying values, one way to associate names with quantities — which is few enough to compile down onto anything and abstract enough to mention no machine at all. That combination sounds paradoxical only while the two senses of low are conflated: the notation is primitive in its vocabulary and entirely machine-independent in its content, and both descriptions hold simultaneously precisely because the vocabulary is about computation rather than about equipment.

There is a sharp test for whether you have actually built such a layer rather than something merely central. Adding a new source language should require a parser plus a set of rewriting rules on top of the existing waist, with no change to the waist. If accommodating a new source means adding a concept to the middle, the middle is not a waist but a growing union of everything above it, and its size will track the number of sources exactly as the connectors it was meant to eliminate did. The same test applies to protocols, data interchange formats, and internal representations far from compilers: the value of a common layer is not that everyone routes through it, but that it can absorb the next arrival without changing.

**Source:** [Lambda: The Ultimate Declarative](../works/lambda-the-ultimate-declarative.md) — the compiler-organization section's discussion of a universal intermediate compilation language, which lays out the product-versus-sum argument for such a layer, diagnoses the historical failures as insufficient generality caused by proposals being too low-level and too much like machine language, and argues that combining the most primitive control operator with the most primitive environment operator puts the notation low enough to be universal yet high enough to be completely machine independent, with a new source language handled by supplying a parser plus the necessary macros.
