# A static structural guarantee is what converts a runtime search into an offset

**Lesson:** Resolving a name at runtime is normally a search: walk outward through nested contexts comparing against everything bound at each level, and the cost grows with both the nesting depth and the number of names. Replacing that search with a direct two-number index — go out this many levels, take this position — is one of the largest wins available, and it is worth being precise about what makes it legal. It is not a clever encoding. It is a consequence of the language having promised that the shape of the runtime contexts mirrors the shape of the source text. Given that promise, the position a name will occupy is determined by where the reference sits in the program, so it can be computed while reading the program and the search never needs to happen.

That relationship is the general one worth extracting: a static analysis is only ever cashing in a guarantee the language made about what cannot vary at runtime. The analysis does not create the information; it discovers information the design already fixed. Which means the value of such guarantees is not aesthetic. Committing to a rule that makes structure predictable is what buys the ability to precompute, and a design that leaves the same thing free produces nothing to precompute and no analysis can recover it.

The exceptions prove the rule and are the practically important part. There is normally one namespace that the design deliberately leaves open — the outermost one, into which names can be introduced and reintroduced at any moment, including after the analysis ran. Nothing about it can be resolved ahead of time, and any attempt to do so would be wrong the first time somebody redefined something. So the analysis must be partial by construction: compute the position where the structure is fixed, and fall back to the search where it is not. A second exception has the same character and is easier to get wrong: a construct that introduces bindings in the middle of a body breaks the parallel between text and runtime structure unless it is first rewritten into the form the guarantee covers. Get that rewriting wrong and the computed positions are silently off by one context.

The transferable habit is to ask, of any optimization that precomputes a location, exactly which guarantee it rests on, and then to go looking for the regions where that guarantee does not hold — because there always are some, and the optimization must degrade gracefully in them rather than being applied uniformly. Precomputed offsets into a schema, resolved handles, direct dispatch through a fixed table, static routes: each is legitimate exactly where something is contractually immutable, and each is a latent fault everywhere else.

**Source:** [Structure and Interpretation of Computer Programs](../works/structure-and-interpretation-of-computer-programs.md) — chapter 5 section 5.5.6 on lexical addressing, which observes that variable lookup as implemented searches frame by frame outward comparing the sought name against every currently bound name, that this is expensive when frames are deeply nested or hold many variables, and that because the language is lexically scoped the runtime environment for any expression has a structure paralleling the lexical structure of the program, so the compiler can determine in advance that a particular reference will be found a fixed number of frames out and at a fixed position within that frame; the introduction of a lookup operation taking a frame number and a displacement, and of a compile-time environment — a list of frames of names with no values — carried as an extra argument through the code generators and extended when a procedure body is compiled, from which those addresses are computed; and the two stated limits, that the footnote to the same section rules out lexical addressing for the global environment because names there can be defined and redefined interactively at any time so the code generators must fall back on the searching operation when a name is not found in the compile-time environment, and that the parallel between lexical and runtime structure does not hold if internal definitions are allowed unless they are first scanned out into ordinary parameters.
