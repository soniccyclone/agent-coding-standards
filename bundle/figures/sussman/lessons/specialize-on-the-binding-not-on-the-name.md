# Specialize on the binding, never on the name, because a name is not an identity

**Lesson:** A tempting way to make a common operation fast is to recognize its name and emit something special. It is easy to implement, it is easy to explain, and it is wrong in a way that will not show up in any test written by the person who implemented it. A name is a reference resolved in some context, and in any language worth using that context can supply a different answer — the name can be a parameter, or shadowed by an inner scope, or reassigned. Recognizing the name and substituting behaviour asserts that the name is a fixed identity, an assertion the language explicitly does not make, and the failure it produces is code that silently does the wrong operation on data the author deliberately supplied a different meaning for.

The fix is to look, not at the name, but at what the name is currently bound to. The apparatus for this usually already exists: an analysis that tracks which names are in scope at each point knows whether a given occurrence refers to something locally introduced or falls through to the outermost context, and the specialization is legitimate exactly in the second case. Consulting it converts a global assertion into a per-site check, which is both correct and strictly more capable, since it specializes everywhere the assumption genuinely holds and quietly declines everywhere it does not.

The other approach — declaring the names reserved so they cannot be rebound — is worse than it looks and worth understanding as a category. It removes an ability programmers had, for the convenience of the implementation. It breaks existing programs retroactively, since a program that happened to use one of the newly reserved names as an ordinary identifier stops working on a system it previously worked on. And the set of reserved names only ever grows, since each new optimization wants another one. Reserving a name is a permanent, backward-incompatible narrowing of the language purchased to avoid writing a lookup.

Even done properly, an honest residual limitation usually remains, and stating it is part of doing it properly. Consulting the scope structure at analysis time settles what a name refers to *then*; it cannot cover a program that reassigns the outermost binding afterwards. That is a real hole, it is much smaller than the one reserving names creates, and its existence is the reason the general principle is worth carrying beyond compilers: any time a system recognizes something by its name and acts on that recognition — a special-cased path keyed on a function name, an interception keyed on a URL, a rule keyed on a field label — it has assumed a stability of naming that nothing enforces, and the assumption should be checked at the point of use rather than declared once at the top.

**Source:** [Structure and Interpretation of Computer Programs](../works/structure-and-interpretation-of-computer-programs.md) — chapter 5, Exercise 5.38, which extends the compiler to generate direct machine operations for selected primitive procedures instead of the general application code, and does so by augmenting the compiler's dispatch to recognize those primitives' names alongside the special forms; its footnote, which states that making primitives into reserved words is in general a bad idea because a user cannot then rebind those names to different procedures, and that adding reserved words to a compiler already in use will stop existing programs that define procedures with those names from working; and Exercise 5.44, which gives the concrete failure — a procedure taking the arithmetic operators themselves as parameters so that a call may supply matrix versions, where the name-recognizing compiler would still emit the primitive operations and ignore the new bindings — and asks for the open-coding compiler to be modified to consult the compile-time environment of section 5.5.6 in order to compile the correct code for expressions involving these names, noting that the result will be correct as long as the program does not define or assign to those names.
