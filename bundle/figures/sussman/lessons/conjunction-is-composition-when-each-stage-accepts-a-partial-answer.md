# Conjunction becomes composition, not intersection, once every stage accepts a partial answer

**Lesson:** There are two ways to satisfy several conditions at once and they look similar on paper and behave nothing alike. The first evaluates each condition independently, producing a full set of things satisfying it, and then intersects the sets. The second gives each condition the accumulated partial answer built so far and asks it to extend that, feeding what comes out into the next condition. The difference is not a matter of efficiency tuning. Under the first scheme every condition must be answerable in isolation, so a condition mentioning two unknowns has to enumerate all combinations before anything constrains it; under the second, a condition arrives with most of its unknowns already pinned down by earlier conditions and has very little left to search.

Making the second scheme possible is a requirement on the individual component, and it is the design decision that everything else rests on: the component must take a partial answer as an input, and must be able to report both that it cannot extend that partial answer and that it can extend it in several ways. Once every component has that shape, the connectives stop being special. Simultaneous satisfaction is series connection — hand the output of one to the next. Alternative satisfaction is parallel connection — give the same input to both and merge. Negation is a filter over the same flow. None of these needs a distinguished implementation, and the description of what they mean is short enough to be obviously right, which is not a small thing given how easy these operators are to get subtly wrong.

The cost has to be stated with the benefit. Because each stage can extend one partial answer into many, a chain of stages multiplies rather than shrinks in the general case, and the amount of work is entirely determined by the order in which the stages were connected — the same conditions, arranged differently, differ by orders of magnitude, since a stage that pins a variable down early makes everything after it narrow. That is the same lesson as constraint ordering in a search, arrived at from the other direction, and it is the price of the compositional structure: you gained uniformity at every connective and gave up any hope that the meaning-preserving reordering is cost-preserving.

The transferable form is a question to ask of any pipeline that composes filters or predicates: does a stage see what previous stages concluded, or only the raw items? A stage that sees only the items is doing independent evaluation and its result must be combined by set operations afterwards. A stage that sees the accumulated partial conclusion can prune, can bind, can fail early, and composes with its neighbours by plain connection. Retrofitting the second onto a system built as the first is expensive, because it changes every component's signature — which is exactly why the shape of the partial-answer object is worth getting right before there are many components.

**Source:** [Structure and Interpretation of Computer Programs](../works/structure-and-interpretation-of-computer-programs.md) — chapter 4 section 4.4.2 on how the query system works: the description of the pattern matcher as taking a pattern, a datum, and a frame of existing bindings, checking consistency with those bindings and returning the frame augmented by any new bindings or else reporting failure; the stream-of-frames organization in which a query is a transformation from an input stream of frames to an output stream of all extensions of every input frame; and the treatment of compound queries, where conjunction is described as a series combination in which the frames passing the first query are filtered and further extended by the second, disjunction as a parallel combination whose two result streams are merged, and where the section immediately notes that because each query may produce more than one output frame per input frame and each conjunct receives its input from the previous one, compound query processing can be slow.
