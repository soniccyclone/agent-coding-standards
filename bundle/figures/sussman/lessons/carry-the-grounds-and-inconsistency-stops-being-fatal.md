# Carry each conclusion's grounds with it, and inconsistency stops being fatal because consistency becomes local

**Lesson:** A system that stores conclusions without recording what they rest on has committed itself to being globally consistent, because a single contradiction anywhere licenses every conclusion everywhere and there is no way to quarantine the damage. That is a brittle contract, and it is not how competent reasoners work: people hold beliefs that cannot all be true simultaneously, notice the collision when it surfaces, and are entertained rather than destroyed by it, because their consistency is local — nothing in their reasoning depended on the whole store being coherent at once. Attaching to every derived value the set of premises it depends on buys a system the same property. A contradiction is then not a fact about the system but a fact about a particular set of premises, so work continues undisturbed in any premise set that does not contain that combination, and the discovery is informative rather than terminal: you learn exactly which assumptions cannot be held together.

Several distinct capabilities fall out of the same bookkeeping, and they are worth listing separately because they have different prices. Knowing the grounds gives provenance — and, more usefully, provenance by absence: if an answer's justification does not mention some input, that input contributed nothing, so a measurement whose omission you can see in the result was a waste of effort, which is a diagnosis you did not have to ask for. It also lets a query be relative to a chosen subset of premises, so questions like "what is the best conclusion available if I decline to trust that source" are answerable without discarding anything already derived, and are reversible: belief can be withdrawn and restored while every derivation performed under any assumption remains on file. And it lets the system explain itself, though this is the expensive tier — a bare set of contributing premises costs a constant factor in space, while retaining how each value was actually derived costs more and pays for itself only in debugging and explanation.

The design discipline is to decide, before adding any of this, which question you intend to ask of a result after the fact. Where did this come from, who deserves credit or blame, what would change if I stopped believing that, and why do you say so are four different questions with four different bookkeeping requirements, and metadata designed for one of them answers the others badly or not at all. What they share is the underlying move, which is worth naming on its own: a value that travels with the reason it exists is a different kind of object from a value that does not, and the difference shows up precisely at the moments when something turns out to be wrong.

**Source:** [The Art of the Propagator](../works/the-art-of-the-propagator.md) — the opening of the dependencies section, which argues from the observation that humans harbour mutually inconsistent beliefs yet do not collapse into deriving everything, and that our belief systems are locally consistent so that on encountering an inconsistency we chuckle rather than crash; the provenance subsection, where a poorly timed measurement is identified as useless precisely because the answer's justification does not mention it; and the alternate-worldviews subsection, where belief in premises can be withdrawn and restored, queries are answered relative to the currently believed subset, derivations already made are retained across those changes, and a discovered contradiction yields the specific set of premises that cannot be held together.
