# Build the algorithm's smallest local element and let the known global algorithm emerge, so neither side has to represent the other's problem

**Lesson:** There are two ways to get a well-studied algorithm working inside a system. The usual one is to install the algorithm as a component and translate your problem into its input language: state the problem in the solver's format, hand it over, decode what comes back. The other is to identify the algorithm's smallest local element, install copies of that element wherever the corresponding situation arises in your own computation, and observe that the ensemble is already performing the algorithm. For a resolution-based search over choices, the local element is small enough to be surprising — a device that offers both answers to a binary question, each one held as true relative to its own freshly manufactured assumption, and that reacts to being told a set of assumptions cannot be held together by ceasing to believe one of them and remembering the prohibition. Scatter these through a computation, add the rule for combining two prohibitions into a third, and what the whole thing does when it hits a dead end is a search of the kind you would otherwise have called a library for.

The reason to prefer the second route is that the problem the algorithm solves never has to exist as a data structure, and that is what removes the boundary. Translating a problem into a solver's format fixes, at translation time, everything that is permitted to constrain the answer: whatever cannot be phrased as an input to the solver cannot participate. When the search is emergent instead, a prohibition is whatever a contradiction turned out to be, and contradictions arise from any computation the system happens to contain, of any kind, including ones with no clean logical statement at all. So arbitrary computation contributes constraints for free, and the search consumes them without anyone having designed the interface between them. The authors of this arrangement name the symmetry exactly: from the search's side, the problem being solved is implicit in the surrounding computation, and from the computation's side, the search is implicit in the ordinary flow of information. That double invisibility is the reliable tell that a facility is in the substrate rather than beside it — a component called by name is visible from both sides, and one that has become part of how the substrate behaves is visible from neither.

The trade is real and should be stated before making it. A mature implementation of a known algorithm carries decades of accumulated engineering that a hand-built local element does not; the version built this way was deliberately the simplest one its authors could manage, with the observation that modern techniques from the literature could be substituted later. So the move is right when what you want is integration — arbitrary parts of your system participating in the algorithm without an encoding step — and wrong when what you want is the last constant factor on a problem you can already state cleanly in the format. The general question to ask of any algorithm you are about to import is which of its parts is genuinely local, because that part is the one that can be dissolved into your own structure, and dissolving it is what buys the integration that calling it never will.

**Source:** [The Art of the Propagator](../works/the-art-of-the-propagator.md) — the implicit-search subsection's guessing device, which manufactures a pair of fresh assumptions and offers each alternative supported by one of them, accumulates reasons against each, and resolves opposing reasons into a prohibition mentioning neither; and the summary observation that the emergent behaviour of many such devices embedded in a network is a distributed incremental search based on propositional resolution, that the structure naturally integrates that search with clauses discovered by arbitrary other computation, that the problem is implicit from the search's point of view while the search is implicit from the computation's, and that this particular solver was made as simple as possible with more sophisticated techniques left available.
