# The cost of a safety check varies per site, so settling it with a global default of off converts an optimization into an unlocatable absence

**Lesson:** Verifying that an operation's precondition holds can easily cost more than the operation itself, and when that ratio is quoted the conclusion drawn is usually a policy: this system does not check. The reasoning is sound about the cost and wrong about the shape of the decision. Whether a particular check is worth its price depends on the site — on how hot it is, on whether something upstream has already established the fact, on what is lost if the precondition is violated there. That is a different answer at every site, and a global default settles all of them identically using information about none of them.

The asymmetry that makes "off" the worse default is what each choice leaves behind. If checking is the default and specific checks are removed, every removal is an act performed somewhere, by an analysis that can be examined or an annotation that can be found, and the ones that remain are visible in the artifact. If not checking is the default, the absent check has no location at all. There is nothing to audit, nothing to grep for, no list of the places where a decision was made, because no decision was made anywhere — the obligation was silently transferred to whoever writes the calling code, in perpetuity, at every site that will ever exist. Obligations transferred that way are not met. They are not met even in code whose authors would have said safety mattered more than speed, because the transfer is invisible and there is no moment at which anyone is prompted to discharge it. The resulting faults are of the worst kind: they do not fail near the omission, they corrupt state or hand control to whoever supplied the input, and they are found by someone who was looking for them.

The construction that dissolves the dilemma is to keep the check as the default, put the elimination in a mechanism rather than in a habit, and expose control over it. Then the expensive cases can still be made cheap — an analysis that proves a fact already established upstream can delete the later test, which is a real and large win precisely because checks cluster redundantly — while the cases nobody analyzed stay safe rather than staying fast. The programmer keeps the ability to trade speed for safety deliberately at the sites where they actually know something, which is the only place that trade can be made competently.

The general principle applies past bounds checking to every defensive measure with a measurable cost: validation at a boundary, an integrity check on stored data, an assertion about an invariant. Ask whether the proposed removal is a decision with a location or a policy without one. A policy without a location is not an optimization; it is the deletion of the record that a question existed.

**Source:** [Structure and Interpretation of Computer Programs](../works/structure-and-interpretation-of-computer-programs.md) — chapter 5 section 5.5.7, the footnote attached to the discussion of interpretation versus compilation: that insisting errors in a user program be detected and signalled rather than being allowed to kill the system or produce wrong answers incurs significant overhead regardless of execution strategy; the example of an out-of-bounds array reference, checkable by validating the reference beforehand at an overhead that can be many times the cost of the reference itself, leaving the programmer to weigh speed against safety; the requirement placed on a good compiler that it be able to produce code with such checks, avoid redundant ones, and allow the programmer to control the extent and type of checking; and the observation that compilers for the popular languages put hardly any error-checking operations into running code so that it falls to programmers to supply the checks explicitly, that people often neglect to do so even in critical applications where speed is not a constraint, and that the 1988 Internet Worm exploited exactly such a missing check on an input buffer in a network daemon.
