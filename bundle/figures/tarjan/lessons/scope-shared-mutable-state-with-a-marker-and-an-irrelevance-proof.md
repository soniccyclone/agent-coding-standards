# Give a subcomputation its own view of shared mutable state with a boundary marker and a proof that the older entries cannot matter

**Lesson:** The algorithm applies itself to sub-problems, and the natural implementation would give each recursive invocation its own bookkeeping structures. That would be fatal: the structures are proportional to the work already done, so allocating or copying them per call destroys the linear bound. What the authors do instead is let the recursive call operate directly on the caller's structures, having first pushed a boundary marker onto one of them, and then prove the two facts that make the sharing sound. On one side, the marker makes the older region unreachable to the sub-problem outright. On the other side, no marker is needed because a property of the ordering guarantees every pre-existing entry lies below the range the sub-problem can ever refer to — the older entries are visible but provably irrelevant. When the call returns, the caller inspects exactly the entries the sub-problem created, resolves them against its own constraints, merges them into a single unit, removes the marker, and continues with the structures in the state its own logic expects.

The general technique is scoping by discipline rather than by isolation, and the price is explicit: you trade a copy for a proof obligation. The obligation has two halves, and both must be discharged deliberately. Nothing the sub-problem does may corrupt what the caller will need afterward, which here is arranged by making the sub-problem's writes land strictly above the boundary. And nothing the caller left behind may change the sub-problem's behavior, which is the half people forget and the half that fails silently — the sub-problem happily reads stale context and produces an answer that is wrong only for inputs nobody tested. This paper handles the forgotten half by name, stating as part of the correctness argument that old entries cannot interfere because of the marker on one structure and the ordering property on the other.

The pattern is worth recognizing because the same trade recurs everywhere a nested computation shares mutable context: a parser that pushes a scope marker onto one symbol table rather than building a child table, an allocator that gives a subtask a region within the parent arena and reclaims by resetting a pointer, a transaction implemented as a savepoint rather than a copy, an interpreter that evaluates a sub-expression on the caller's stack. Each buys real performance and each is only correct under an argument about visibility that the code does not express. So the rule is not to avoid the technique — it is often the only affordable option — but to write down the two-part argument next to the marker, and to prefer a boundary that makes the older region *inaccessible* over one that merely makes it *unused*, since the first is enforced by the mechanism and the second only by the reasoning.

**Source:** [Efficient Planarity Testing](../works/efficient-planarity-testing.md) — the step that implements recursive application of the embedding algorithm by placing an end-of-stack marker on one of the two stacks before the recursive call, inspecting only the blocks the call created, rejecting the graph if any of them has entries on both sides, moving the remainder to one side, combining them into a single block, and deleting the marker; together with the lemma's proof that old entries on the two stacks and the block stack cannot interfere with the recursive application because one stack carries the marker and every entry on the other is bounded by the sub-problem's lowest attachment point, and the observation that on return the structures hold exactly what the outer level needs to continue.
