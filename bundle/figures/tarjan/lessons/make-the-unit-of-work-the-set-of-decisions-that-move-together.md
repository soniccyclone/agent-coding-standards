# Make the unit of work the set of decisions that are forced to move together

**Lesson:** The construction at the heart of this algorithm keeps making binary choices — each piece of the graph goes on one side of a cycle or the other — and the choices are not independent. Committing one piece to a side forces some other pieces to the same side and some to the opposite side, so a later step may have to flip a whole population of earlier decisions at once. Handled naively that flip costs time proportional to how many decisions it touches, and the flips are frequent, so the algorithm would be superlinear. The fix is to stop treating the individual decision as the unit. The authors define a *block*: a maximal set of decisions with the property that fixing any one of them fixes all the others. Blocks partition the outstanding decisions at all times, and a flip is always a flip of an entire block, never of part of one. So the operation that looked like it touched many things touches exactly one thing, once you have named the right thing.

Two supporting facts turn that definition into a linear-time algorithm, and both are the real work. The first is a structural theorem: the members of a block always occupy contiguous positions in the two sequences the algorithm maintains, and each block spans a contiguous range of the underlying order. Contiguity is what allows a block to be relocated by adjusting a constant number of links rather than by walking its members, and it is proved by induction over the algorithm's own steps rather than assumed. The second is that blocks merge as constraints accumulate — when a new decision forces several previously independent blocks together, they become one block, and the merge is also a constant-time operation. The number of merges is therefore bounded by the number of decisions, which is what caps the total work.

The transferable pattern is to look for the equivalence classes induced by your constraints, and then to build the representation around those classes rather than around the individual items. Two questions decide whether the pattern applies. Is there a relation "deciding this forces that" whose transitive closure you can maintain cheaply? And can you arrange the representation so each class is contiguous, so that acting on a class is a pointer operation instead of a traversal? When both answers are yes, an operation whose cost seemed proportional to the size of the affected set becomes constant, and the reasoning gets simpler at the same time, because the invariant to maintain is now about whole classes rather than about individual members. The same shape recurs in union-find over constraints, in propagating a sign flip through a system of coupled variables, and in any settings-propagation problem where changing one value obliges you to change a cluster of others: the win comes from discovering the cluster before the propagation happens, not from making the propagation faster.

**Source:** [Efficient Planarity Testing](../works/efficient-planarity-testing.md) — the embedding section's introduction of a block as a maximal set of stack entries such that the placement of any one of the corresponding pieces determines the placement of all the others, its statement that blocks always partition the stack entries, the lemma proved by induction over segments embedded and entries deleted showing that a block's entries are adjacent in each of the two stacks and span a contiguous range of the cycle's vertices, the resulting implementation in which a block is switched between sides by exchanging list pointers at its two ends, the separate stack maintained to record block boundaries, and the merging of previously separate blocks into one when a newly embedded path constrains them together.
