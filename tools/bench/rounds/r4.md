Two additions.

First, a second consumer needs to observe every job state transition, in the
order the transitions happened, and must be able to resume from where it left
off after being stopped for an arbitrary period.

Second, an admin view reporting the count of jobs in each state. The counts must
be correct when read while workers are actively running.

Expose these from the same `jobqueue` module:

    q.transitions(after=None)  ordered iterable of transition records, each with
                               a .cursor, a .job_id and the state moved to;
                               passing the last-seen .cursor resumes after it
    q.counts()                 dict mapping state name to number of jobs in it

Update the tests and the README.
